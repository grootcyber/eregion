### Changed
- **The weekly advisory issues say what a human accepted, and an accepted advisory turns the run red no more** (DEP4, #990; tenth review pass, P10-10). The five advisories open since 29/10 and 17/11 were each accepted with their reason in `requirements/audit-accepted.json`, yet their issues said nothing of it and the weekly run went red on 17/11 for one accepted three days before: advisories dealt with looked abandoned. `scripts/pip_audit_issues.py issues` now reads that list by default (no change to `pip-audit.yml`): an accepted advisory's issue carries « Accepté le … » and the maintainer's reason in its body (an `@` written so it pings no one), and opening, reopening or finding it back no longer makes the run red. Withdrawing an acceptance turns the run red, once. The reason is written on one line, inert (`<` and `>` as entities, so it can carry no issue's key; no mention), at most 1 000 characters, and its date must be a real one, not to come. A human still closes the issue. In `issues` mode, a broken list now stops the weekly handling (exit 2); `ci.yml`'s `pr` check already refuses it in the pull request that breaks it. An acceptance never expires: an age past which it would is another lot, a risk assumed. `docs/operations.md`, « Les avis acceptés ».
  - Tests: `tests/unit/test_pip_audit_issues.py` (opened, rewritten without a comment, reopened, found back, no mention, a reason carrying a key, a withdrawal, no real date, too long, an unreadable list). Mutants M6812–M6814, M6851–M6854 (`scripts/mutants/DEP4.py`).
