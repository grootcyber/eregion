### Fixed
- **The weekly drill's dry check says the scheduled start's state against the arming, and the arming guards Orodruin's shutdown of 23:00 UTC** (DRL1e, part of #613; `docs/design/drill-banc.md` §16). An apply that redeploys the Logic App puts it back to `Disabled`: the arming on Orodruin's disk still said armed, `make orodruin-drill-check` said « ✓ scheduled start », and the missed occurrence was seen only as Imladris's `not_run`. The check now reads the Logic App's `properties.state` in the same read as its trigger's hour, by the operator's `az login` and the read right the arming already needs, and says « armed but scheduled start disabled: re-arm » (exit 1); armed with a state that does not read (the read refused, the state absent, another state), it says so and never takes it for enabled; nothing armed and the scheduled start enabled is a warning. An unreadable Logic App no longer stops the check before the arming and the dry run are said. The reading is instant: an apply after the check is seen at the next check. The arming (and the check) now refuse a drill whose budget, its hour plus its `max_run_s`, reaches Orodruin's daily shutdown of 23:00 UTC, or whose wake-up 20 min before falls before it, and warn when only the service's ceiling (`RuntimeMaxSec`, then the stop's grace) reaches it; the shipped drill passes silently. Two tests are tightened: the search for an apply enabling the scheduled start reads every `.tf` of the module, and the parity of the drill's options with the injector's runs reads the `Makefile`'s run definitions up to the image, so that an option posed after `--env-file` is seen.
