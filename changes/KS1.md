### Security
- **A campaign whose kill switch cannot be read stops, and a kill switch set during a run is no longer overwritten** (KS1, #648; `docs/operations.md`). `annatar campaign run` re-reads its manifest's `kill_switch` through the bounded reader of `runs/` (SEC-A1) before each run and before each write of the manifest; a stop once seen is kept and never overwritten by what the runner writes from memory. Previously the runner rewrote the whole manifest during and after each run, erasing a `kill_switch` set meanwhile. A manifest that is absent (deleted from outside: the runner never leaves it absent), refused by the reader (a pipe, a link, a file too large) or unreadable (not JSON, nested too deep, an I/O error, not an object, a `kill_switch` that is neither true nor false, `null` included) now stops the campaign (`aborted`, exit code 1) instead of letting it continue; so does a stop seen during the last run. The reason is said once in the runner's output and recorded in the manifest as `stop_reason` (`"kill switch set"` for the operator's stop). A campaign directory deleted while the campaign runs is never recreated. When the manifest is loaded, `kill_switch` counts as set only when it is `true`.
  - Tests: `tests/unit/test_campaign_runner.py`. Mutants M4573–M4578.
