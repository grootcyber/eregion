### Security
- **Both images install `libc6` and `libc-bin` at their fixed version, a second written and dated exception to « no `apt-get upgrade` »** (LIBC1, #1098; `docs/operations.md`, « Les images publiées »). The base `python:3.12-slim`, pinned by its digest (still the latest on 23/11), carries `libc6` and `libc-bin` `2.41-12+deb13u4`, with CVE-2026-19499 and CVE-2026-5435 (High), fixed upstream in `2.41-12+deb13u5`; measured on the base image, that version comes from trixie, the point release 13.8, with no DSA. No digest of the base carried the fix yet, so the release gate refused both images. `glorfindel/Dockerfile` and `annatar/Dockerfile` now install both packages, each named at that exact version, in one layer right after the `zlib1g` one (ZLIB1), as root, byte for byte the same in both: never an upgrade, never a free version. The header of both Dockerfiles lists the exceptions. If Debian replaces that version, the build breaks loudly, on purpose. The layer is removed in the pull request of the base's bump whose digest carries `+deb13u5` or newer. The release gate is unchanged and as strict: both images, built and scanned on 23/11, show no High or Critical CVE fixed upstream in their system packages.
  - Tests: `tests/unit/test_image_cves.py` (the same layer in both Dockerfiles, both packages at the exact version, right after ZLIB1's and before any `USER`, its reason and its removal said, the header listing the exceptions; the versions read in images already built when `EREGION_LIBC1_IMAGES` names them); mutants M7167–M7171 (`scripts/mutants/LIBC1.py`).
