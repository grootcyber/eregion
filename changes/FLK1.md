### Fixed
- **The test suite fetches ChromaDB's embedding model by one process at a time, and only when a test needs it** (FLK1, #723; `docs/operations.md`, « Ce que la CI retente »). In `pytest -n 4` with an empty throwaway HOME, two workers fetched the model into the same `~/.cache/chroma` at once (a real `CycleMemory` in `test_agent_nodes.py`, the campaign report's index in `test_containment.py`); ChromaDB writes the archive in place and removes it when its SHA-256 does not match, so one removed the other's half-written file (`FileNotFoundError` on `onnx.tar.gz`), reproduced at the first full run. In each process of the suite, the conftest now wraps ChromaDB's own check-then-fetch (`ONNXMiniLM_L6_V2._download_model_if_not_exists`) in a file lock beside the model, when ChromaDB is imported (`scripts/chroma_model.py`, `lock_downloads`): a session that never embeds a text fetches nothing; the first process that needs the model fetches it, the others wait, then find it there. The lock is re-entrant within a process; a cache that is not writable (one root still owns) or a ChromaDB without that method is said as a warning, never an error of the suite. `python scripts/chroma_model.py` (CI8) and the mutation harness's preparation (CI6b) take the same lock.
  - Tests: `tests/unit/test_chroma_model.py` (three workers embedding at once on a fake ChromaDB that writes its files in place, slowly: fetched once; a session that embeds nothing fetches nothing; a second process waits for the lock, by a handshake; a read-only cache; the locked ChromaDB still has the method), `tests/unit/test_mutation_shards.py`. Mutants M4790–M4793, M4807–M4809.
- **The guard of Imladris's name reads `git ls-files -z`** (FLK1, #723; `scripts/host_name.py`). Without `-z`, git quotes a name that is not ASCII, which names no file: its content was skipped, unsaid (the second review of IML1).
  - Tests: `tests/unit/test_host_name.py`. Mutant M4794.
