### Fixed
- **The test suite fetches ChromaDB's embedding model once per session, never by two workers at once** (FLK1, #723; `docs/operations.md`, « Ce que la CI retente »). In `pytest -n 4` with an empty throwaway HOME, two workers fetched the model into the same `~/.cache/chroma` at once (a real `CycleMemory` in `test_agent_nodes.py`, the campaign report's index in `test_containment.py`); ChromaDB writes the archive in place and removes it when its SHA-256 does not match, so one removed the other's half-written file (`FileNotFoundError` on `onnx.tar.gz`), reproduced at the first full run. Each process of the suite now goes through `prepare_once` (`scripts/chroma_model.py`) before its first test, under a file lock beside the model: the first fetches it, the others find it there; a model already there is neither imported nor fetched (no network); a preparation that fails is said as a warning, never a verdict. `python scripts/chroma_model.py` (CI8) takes the same lock.
  - Tests: `tests/unit/test_chroma_model.py` (a session in `-n 3` on a fake ChromaDB that writes its files in place, slowly: the model ready before each test, fetched once; a second process waits for the lock, then finds the model there). Mutants M4790–M4793.
- **The guard of Imladris's name reads `git ls-files -z`** (FLK1, #723; `scripts/host_name.py`). Without `-z`, git quotes a name that is not ASCII, which names no file: its content was skipped, unsaid (the second review of IML1).
  - Tests: `tests/unit/test_host_name.py`. Mutant M4794.
