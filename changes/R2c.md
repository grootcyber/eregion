### Added
- **The dedicated run is wired from the sandbox, and a fault can never be routed through Stratus** (R2c, pièces 4B/4D, docs/design/stratus-cible.md « Le code hermétique de R2c »). `make orodruin-stratus` runs a Stratus technique under the dedicated identity by the federated exchange, FROM the hardened sandbox (pièce 3): on the armed host (where the IMDS is reachable) `annatar.executors.stratus_assertion` fetches Orodruin's managed-identity assertion for the exchange audience (`api://AzureADTokenExchange`), written to a host file; the run then starts on the `eregion-stratus-sandbox` network (where the IMDS is DROPped), the assertion mounted read-only and named by `EREGION_STRATUS_ASSERTION_FILE`, so `stratus_run_env` turns it into `ARM_USE_OIDC` and the provider exchanges it for a Stratus token on the dedicated subscription — never Orodruin's managed identity (unreachable from the sandbox) nor the bench. An empty assertion fails closed (the run does not start). The Stratus scope runs control-plane TECHNIQUES only: a `kind: fault` scenario (Gothmog's engine) is refused at authoring, beside the existing VM-target refusal (#819). The FIC scenario no longer claims a Graph probe — under the closed role it has no directory read, so it is verified on the activity log, not the directory.
  - Tests: `tests/unit/test_annatar_stratus.py` (the assertion is fetched for the exchange audience and fails closed when empty; the `orodruin-stratus` run is on the sandbox network with the assertion mounted read-only and named, the assertion fetched on the host for the exchange audience; a `kind: fault` stratus scenario is refused) and `tests/unit/test_provider_boundary.py` (the assertion module is a declared azure adapter). Mutants M6606 (kind:fault no longer refused), M6607 (the wrong exchange audience), M6608 (an empty assertion not fail-closed), M6609 (the sandbox network dropped for the host network), M6610 (the token file no longer named), `scripts/mutants/R2c.py`.
- **The sandbox guard proves the IMDS cut by a file, not by live iptables (decision A)** (R2c, pièce 3 corrected, docs/design/stratus-cible.md « Le code hermétique de R2c »). `orodruin-check` runs in a hardened container (`--cap-drop ALL`, its own netns) that can neither run `iptables` nor see the host's `DOCKER-USER` chain — so `read_sandbox`'s live read would always be unreadable and the contract could never arm for Stratus. Now the root service that poses the DROP rule also writes `iptables -S DOCKER-USER` to a file (`/run/eregion-sandbox-rules`) and a systemd timer re-poses the rule and rewrites the proof (`infra/orodruin/main.tf`); `read_sandbox` reads that mounted file (`ORO_RUN_CONTRACT` and the engine run `ORO_RUN_ENGINE` mount it read-only) and **refuses a stale proof** (older than `SANDBOX_PROOF_MAX_AGE_S` — the timer has not refreshed it, so the rule is not proven now), a missing one, or one without the DROP (fail closed). The only privileged actor stays the root poser; the sandbox run never gets `NET_ADMIN`. Decision made with Jonathan, 20/11 (the boundary — how the contract trusts the IMDS is cut).
  - Tests: `tests/unit/test_stratus_contract.py` (the proof fresh with the rule arms; a stale proof, a missing one and an absent rule each fail closed) and `tests/unit/test_orodruin.py` / `test_annatar_stratus.py` (the cloud-init writes the proof and the timer, the proof is mounted into the contract and the engine run). Mutants M6611 (freshness dropped), M6612 (the proof not written), M6613 (the timer not enabled), M6614 (the proof not mounted), `scripts/mutants/R2c.py`. Proven end to end at the bench (ID1c).
- **The run is a sidecar: the engine keeps the controls on the bridge, only the third-party Stratus subprocesses detonate in the sandbox** (R2c, pièce 4 corrected, docs/design/stratus-cible.md « Le code hermétique de R2c »). The sandbox (pièce 3) blocks the IMDS — but the engine NEEDS the IMDS on the bridge for everything that is Orodruin's: the contract's arming, the watch gate and its mid-cycle re-check, the exercise window, the read-only Graph probe, the control-plane enrollment guard and the journal. Running the whole `annatar run` in the sandbox would starve all of those (the run refuses, "no live watch", measured at the bench). So the run is split: a **detonator** container (`ORO_RUN_DETONATOR`, `annatar.executors.stratus_detonator`) runs on the sandbox network under the federated assertion and executes only the four raw Stratus phase subprocesses; the **engine** (`ORO_RUN_ENGINE`) stays on the bridge under Orodruin's identity, keeps every control, and delegates each phase to the detonator through a shared IPC directory (request/response JSON files — never a network between them, never the docker socket). Orodruin's run mounts never enter the detonator, so a compromised Stratus library cannot read Orodruin's managed-identity token even over the IPC channel (only a phase name crosses). `make orodruin-stratus` fetches the assertion on the bridge, starts the detonator, runs the engine, then removes the detonator (torn down even when the run fails). `StratusExecutor(detonate=…)` takes the delegate; `run_subprocess` is the raw phase the detonator runs (no journaling), `run_phase` journals on the engine then delegates. Decision made with Jonathan, 20/11 (why the whole run cannot move into the sandbox).
  - Tests: `tests/unit/test_annatar_stratus.py` (the engine delegates each phase to the detonator and never runs the subprocess on the bridge; the detonator stops only on `__stop__`, reports a crash as a failure, pairs each response to its request by id, and a never-answering detonator is a timeout not a success; the delegate is built only with an IPC directory; the `ORO_RUN_DETONATOR` / `ORO_RUN_ENGINE` macros and the `orodruin-stratus` recipe split the sandbox from the bridge). Mutants M6641 (the delegate ignored — the subprocess runs on the bridge), M6642 (a phase mistaken for the stop sentinel), M6643 (a crash answered as success), M6644 (the id pairing dropped), M6645 (a timeout answered as success), M6646 (the response never written), M6647 (the delegate built only without an IPC dir), M6648 (the detonator never started), M6649 (the detonator never torn down), M6650 (Orodruin's mount leaked into the detonator), M6733 (the response written before the request is cleared, so the engine's next request is clobbered — a cross-process race found in review, fails closed), `scripts/mutants/R2c.py`. Proven end to end at the bench (ID1c, 20/11 — a real T1133 bastion-shareable-link write from the sandbox, escalated by the deployed Glorfindel).
