### Changed
- **The certificate Azure puts on a managed identity it creates no longer makes a high `entra-credential-added` card; it is set aside, counted and said** (MID1, #981; `docs/glorfindel.md`, « Le certificat qu'Azure pose sur une identité managée »; `docs/operations.md`, « Le principal Managed Service Identity (MID1, #981) »; `infra/glorfindel-host/README.md`). On 20/11 on Imladris, the drill's Logic App, created again after failed applies, made five high cards (six rows), « credential added (Add service principal) by Managed Service Identity », each time another principal, all judged Wrong: Azure itself creates the managed identity's service principal and puts a certificate on it. Entra's adapter now sets such a row aside (`glorfindel/providers/azure/entra_msi.py`, called by the RulePoller through `DetectionConnector.set_aside`, before any routing) only when all of it holds: its `ActorId` is, without case, the object id of the tenant's « Managed Service Identity » principal, given outside the repository (`EREGION_ENTRA_MSI_ACTOR_ID`, the watch's environment, Imladris's `host.env`), never its display name; its operation is « Add service principal » and its target a `ServicePrincipal`; every credential it added is a key description of type `AsymmetricX509Cert` and usage `Verify`, each key once; and the row is not marked as Glorfindel's (`GlorfindelIdentity`, `GlorfindelManaged`: a credential added on its identity stays critical, whoever its author). The same name under another `ActorId`, « Update application », « Certificates and secrets management », another target, a human, an application, a secret, another usage, a federated credential, a certificate beside a secret: a high card, as before. Without the variable, or with a value that is no object id, nothing is set aside, and it is said in the rule's status at each pass, once in the watch's log, and in the console; `host_env.py --check` (and the writing of a new `host.env`) refuses a value that is no GUID, never printing it. What is set aside is counted in the rule's status (`msi_certificate`, cumulative), said in the watch's log, shown on the rule's line in the console (« N MSI ») and in its details. The shipped rule only, by its name and its query to the byte (ATT1's shape): a rule of the client's layer that changes its query keeps its cards. The shipped query does not change; the variable reaches the watch alone (`docker-compose.yml`).
