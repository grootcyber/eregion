### Added
- **The boundary between the Orchestre and a dedicated Annatar session, written; the main checkout moved forward after each merge** (FRN1, #803; `docs/sessions.md`, « La frontière rouge » and « Relecture et fusion »; `.claude/skills/elrond/SKILL.md`, principle 8, the plan's header, `init`, `run`, `status`; `docs/elrond.md`; `CLAUDE_ANNATAR.md`). An attack lot (a technique from a pinned public library, on Annatar's side) is one by its nature, set in advance in the roadmap, never because a safeguard stopped it. It lives end to end in a dedicated Annatar session, which works on the whole brief and holds its Opus 5.5 review, its published verdict, its PR and its merge, at the place the Orchestre gives it in the merge train, never between the release gate and the version PR. The Orchestre coordinates and needs no content: it never reads the brief, the diff or the report; it opens the issue under a neutral title, hands out the mutant range and the merge order blind, and records a neutral state in the plan's index and in the manual. The issue's body, the neutral titles and the index's neutral label are written by the dedicated session or by Jonathan; a `Neutral index: <date>` line in the plan's header, read before the index, says the index names no technique, and without it the Orchestre asks before reading. Messages between the two sessions stay neutral, for coordination only, never for the work or to get a request through. A lot stopped by a safeguard stays in its session and follows the planned fallback: it is never handed to another session or agent. This is not a workaround: the same safeguards hold there, and a stop is handled as anywhere else (fallback, then an Opus 5.5 review; if it switches too, the traced 4.8 review and the merge on Jonathan's word). Still to be settled by Jonathan: an attack lot's changelog fragment, which `make release` assembles in the Orchestre's version PR. After each merge, whoever merged moves `~/eregion` forward on `origin/main` with a command that does nothing off `main` or on a dirty tree and says so (`make install` too when `pyproject.toml` changed): the editable venv points there, so agent probes (HY2b), the CLI and the tools run on that code.
