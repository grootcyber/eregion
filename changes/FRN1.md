### Added
- **The boundary between the Orchestre and a dedicated Annatar session, written; the main checkout moved forward after each merge** (FRN1, #803; `docs/sessions.md`, « La frontière rouge » and « Relecture et fusion »; `.claude/skills/elrond/SKILL.md`, principle 8, `run`, `status`; `docs/elrond.md`). An attack lot (a technique from a pinned public library, on Annatar's side) lives end to end in a dedicated Annatar session: its work, its Opus 5.5 review, its published verdict, its PR and its merge. The Orchestre never reads its brief, its diff or its report: it hands out the issue, the mutant range and the place in the merge order blind, and records a neutral state in the plan's index and in the manual. The index holds such a lot under a neutral label, written by the dedicated session or by Jonathan, never by the Orchestre, which asks for it rather than read an index that still names a technique. Messages between the two sessions stay neutral: the issue, the branch, the PR, the state. This is not a workaround: the red work stays under the same safeguards in its own session, and a stop there is handled as anywhere else (fallback, traced review, merge on Jonathan's word). After each merge, whoever merged moves `~/eregion` forward on `origin/main` (`git merge --ff-only`, a clean tree on `main`): the editable venv points there, so agent probes (HY2b), the CLI and the tools run on that code.
