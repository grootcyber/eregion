### Fixed
- **The invariant machine no longer holds a release to account for an older isolation on an NSG that nothing ties to the NIC any more, when the only state that held the NIC bare recorded that it had no NSG** (INV8, #1105; `docs/design/preuves.md`). The 0.6.5 release gate (seed 152578281, 2 000 sequences) failed I8 on a sequence that is red on v0.6.4 too: the isolation code has not changed since, and the new seed drew it. An older version had isolated `api` on its own NSG. `api` went into quarantine, someone left its NIC bare, and the quarantine's tags and the VM's state were lost: nothing tied the NIC to that NSG any more. Isolated again while bare, Glorfindel recorded "no NSG", the only thing it could know. A partial reset then put the NIC back to that "no NSG" and kept the state. The next isolation and release were right: `released`, the NIC bare, as recorded. The oracle read the kept state, which held the NIC bare, as one that knew our NSG had been taken off. It then counted the older isolation on that NSG, which no longer governs the NIC, against the release. Glorfindel cannot know about it. The code is unchanged. Now a state counts that way unless it records "no NSG" for a NIC that the test's journal saw go into quarantine bare. A state that does not know the original, or a "no NSG" that the journal contradicts, still counts. What remains is open, and old (accepted since I8F): the older isolation stays, under its fixed names, on an NSG that governs nothing, and nothing tells the operator; `find_orphan_rules()` and `sweep_vm_rules(dry_run=True)` do not see it. If the operator puts that NSG back on the NIC, the VM is cut off and Glorfindel says nothing. In the machine, it is the test's operator that puts the NSG back. The maintainer's decision (23/11): say it, never remove it — the orphan sweep will report a pair of fixed-name isolation rules on an NSG attached to nothing as a possible older isolation of Glorfindel, with the command to remove it, and will never remove anything itself, a name proving nothing about whose rules they are; a small lot of its own, after 0.6.5.
  - Tests: `tests/unit/test_invariant_regressions.py::test_a_nic_isolated_bare_after_the_loss_held_bare_again_doesnt_carry_its_rules` (three ways the NIC is left bare again: a reset cut short, a release cut short, someone; red on `origin/main` and on v0.6.4), and `test_a_none_recorded_over_an_unknown_is_still_judged` (the other side). `test_a_bare_nic_whose_state_knows_its_original_is_not_isolated_as_none` (the review's world: the exemption now reads the state's "no NSG", and a known original read as "no NSG" stays caught).
