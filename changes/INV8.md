### Fixed
- **The invariant machine no longer holds a release to account for an older isolation on an NSG that nothing ties to the NIC any more, when the only state that held the NIC bare recorded that it had no NSG** (INV8, #1105; `docs/design/preuves.md`). The 0.6.5 release gate (seed 152578281, 2 000 sequences) failed I8 on a sequence that is red on v0.6.4 too: the isolation code has not changed since, and the new seed drew it. An older version had isolated `api` on its own NSG. `api` went into quarantine, someone left its NIC bare, and the quarantine's tags and the VM's state were lost: nothing tied the NIC to that NSG any more. Isolated again while bare, Glorfindel recorded "no NSG", the only thing it could know. A partial reset then put the NIC back to that "no NSG" and kept the state. The next isolation and release were right: `released`, the NIC bare, as recorded. The oracle read the kept state, which held the NIC bare, as one that knew our NSG had been taken off. It then counted the older isolation on that NSG, which no longer governs the NIC, against the release. Glorfindel cannot know about it. The code is unchanged. Now a state counts that way unless it records "no NSG" for a NIC that the test's journal saw go into quarantine bare. A state that does not know the original, or a "no NSG" that the journal contradicts, still counts. The way out is unchanged: once the NSG is back on the NIC, the release sweeps the older isolation.
