### Added
- **The mutants only an invariant machine kills, measured each night before the release gate finds them** (MUT7, #699 ; `scripts/mutation_night.py`, `.github/workflows/mutants-night.yml`, `docs/operations.md`, `docs/design/preuves.md`). On 10/11 the 0.5.9 gate was held five times, one mutant after the other (M21, M606, M09, M13, M33), each let through by some draws of the seed. A mutant is taken when its target reaches the test that runs a machine, word by word: a plain test of a machine's file, or a `-k` that leaves the machine out, is no machine (file by file, `mutation_check.machine` counts nine such targets). `alone` when the target runs nothing else (43 on 10/11); `beside` when it also names fixed tests (198), which run first, once: if they catch the mutant, the machine is not run on it — unless they draw (Hypothesis) or race, then the whole target runs on each seed, never a false green. Each night takes a seventh of the list (a mutant's night is fixed by its id, the whole list in a week) at the gate's 500 sequences on three seeds drawn, after each unmutated machine on each seed. Each mutant is said `CAUGHT n/n`, `flaky` or `SURVIVES`; a fragile one comes with the seeds it survived on and, for each, the command that measures it as the gate does. The workflow, pushed by Jonathan (the sessions' App has no Workflows right), opens or comments a neutral issue per fragile mutant from a job of its own (`issues: write`, no checkout, no action, what the night said checked against its form first); the remedy is a frozen sequence linked by `TESTS_ALSO`, as MUT5, MUT6 and MUT8 did. Estimated budget: 15 to 45 min of wall time a night on one runner.
