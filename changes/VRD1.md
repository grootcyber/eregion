### Added
- **A finer verdict: a wrong says whether it was a false alarm or an action too strong** (VRD1, #1285; `docs/observation.md`, `docs/design/memoire.md` §9.6). Jonathan's decision (24/11): a « wrong » tells a false alarm (nothing happened) from an action too strong (the signal was real, the gesture too strong). `verdict` stays the verdict; the cause is a field beside it, `verdict_cause` (`false_alarm`, `too_strong`), optional, on a wrong only (`glorfindel/verdict_cause.py`). A wrong given before, or without a cause, carries none and reads as it did everywhere — « wrong », counted « cause unsaid », MEM2b's text in the memory; a card judged again never keeps its former cause; a cause the store holds is said only when it is one of the two. « Too strong » only after a gesture — the card's action responded to a threat (isolate, block, snapshot, restore…: MEM2b's reading, one definition): on a card that made none the store refuses it, whoever asks, and on a detection without an action a wrong is a false alarm, the one wrong the console and Discord offer there. The console's buttons (TO JUDGE, the card's window, the 360°'s bubble, the batch of JUG3): ✓ Right, ✗ False alarm, ✗ Too strong after a gesture, ? Unsure; a verdict given says its cause (« judged: wrong · false alarm »). Discord: the same buttons, out of `bot.py` (`glorfindel/bot_verdict.py`), each writing the cause clicked; a message posted before keeps its ✗ Wrong once the bot restarts (a wrong without a cause, as it did), and a card's signature is the one of before: no message is edited for this alone. The command: `glorfindel verdict <id> wrong --cause false_alarm|too_strong`. `glorfindel report` and `/api/report` count the two causes apart, on every card and on the disruptive ones; the rate of the disruptive ones judged wrong keeps its definition — both causes count in it, each said beside it; the overview's WRONG DISRUPTIVE and the Monday summary say them. The memory by keys says the cause (« fausse alerte : rien ne s'était passé », « action trop forte : le signal était vrai, le geste trop fort »); with MEM2's switch off, what the model sees is origin/main's to the byte — the model's part is checked at ENQ5b's end-to-end run.
