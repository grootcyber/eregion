### Security
- **The installation of Imladris's CD lives in a script the code owners hold; the `Makefile` target only calls it** (CDI1, #918; `infra/glorfindel-host/README.md`, « Le CD d'Imladris »; `docs/design/modele-de-menace.md`, §7; `docs/sessions.md`, « Les règles du dépôt »). `make imladris-cd-install` copies the CD's files and `discord.env` to Imladris and runs `install.sh` there with sudo; its recipe lived in the `Makefile`, which `.github/CODEOWNERS` does not own, so a change there changed what is installed as root on Imladris without a code owner's approval. The recipe is now `infra/glorfindel-host/cd/install_from_workstation.sh`, under the CD's owned directory: the same gestures, in the same order, each stopping the installation when it fails — the webhook and the mention read on the workstation (never the bot's token), `~/.eregion-cd` created 700, the files copied, cosign downloaded by the VM and kept only at its pinned sha256, `discord.env` written under `umask 077`, `installed-from`, then `install.sh` with sudo in a terminal. The target checks Imladris's host key, then passes the script the address, the user, the SSH options and the list of files. Since the `Makefile` stays unowned, the script refuses before any gesture SSH options that do not pin the host key (`StrictHostKeyChecking=yes`) and a list of files other than its own: `scp` copies by file name, and another list could put any file of the checkout under the name of one of the agent's files.
  - Tests: `tests/unit/test_host_cd_install.py` runs `make imladris-cd-install` against a fake `ssh` and a fake `scp` that note their arguments and their input, and keeps the gestures and their order, the stop at each failed gesture, the refusals, and the target reduced to the call; `tests/unit/test_codeowners.py` keeps the script under a line of the CODEOWNERS (mutants M6351–M6360, `scripts/mutants/CDI1.py`).
