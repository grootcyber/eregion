### Security
- **The installation of Imladris's CD lives in a script the code owners hold; the `Makefile` target only calls it** (CDI1, #918; `infra/glorfindel-host/README.md`, « Le CD d'Imladris »; `docs/design/modele-de-menace.md`, §7; `docs/sessions.md`, « L'identité des sessions »). `make imladris-cd-install` copies the CD's files and `discord.env` to Imladris and runs `install.sh` there with sudo; its recipe lived in the `Makefile`, which `.github/CODEOWNERS` does not own, so a change there changed what is installed as root on Imladris without a code owner's approval. The recipe is now `infra/glorfindel-host/cd/install_from_workstation.sh`, under the CD's owned directory: the same gestures, in the same order, each stopping the installation when it fails — the webhook and the mention read on the workstation (never the bot's token), `~/.eregion-cd` created 700, the files copied, cosign downloaded by the VM and kept only at its pinned sha256, `discord.env` written under `umask 077`, `installed-from`, then `install.sh` with sudo in a terminal. The target runs the host key's check, then passes the script the address, the user, the SSH options and the list of files. The script refuses, before any gesture, SSH options other than the form the `Makefile` computes, word for word (ssh keeps the first value of an option: a `StrictHostKeyChecking=no` before the pinned one, `-F`, `ProxyCommand`, `ProxyJump` or `KnownHostsCommand` would undo the pinning), and a list of files other than its own (`scp` copies by file name: another list could put any file of the checkout under the name of one of the agent's files). What this closes: the installation's recipe, owned, and a drift of its options or files caught. What it does not stop: a hostile `Makefile`, which may not call the script. The SSH options, the host key's check (`imladris-known`, `infra/glorfindel-host/known_host.sh`), the recipes that run sudo on Imladris (`imladris-cd-enable`, `-cd-disable`, `-cd-uninstall`) and every other recipe stay outside the code owners (the maintainer's decision of 18/11), said as open in the threat model (follow-up: CDI2, #922). The script also refuses an address that is not an IPv4 address and a user that is not a Unix user name: `user@address` is ssh's last word before the command, and a user `-oProxyCommand=…` would arrive as an option.
  - Tests: `tests/unit/test_host_cd_install.py` runs `make imladris-cd-install` against a fake `ssh` and a fake `scp` that note their arguments and their input, and keeps the gestures and their order, the stop at each failed gesture, the refusals (the SSH options that undo the pinning among them), and the target reduced to the call; `tests/unit/test_codeowners.py` keeps the script under a line of the CODEOWNERS (mutants M6351–M6365, M6381–M6383, `scripts/mutants/CDI1.py`).
