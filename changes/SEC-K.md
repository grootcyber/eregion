### Security
- **`.github/CODEOWNERS` names only what the workflows that hold a credential run, and a test keeps it so** (SEC-K, #847; `docs/design/modele-de-menace.md`, §6 and §7; `docs/sessions.md`, « Les règles du dépôt »). The catch-all line and the indicative paths are gone. What stays: each file of the repository that a job holding a secret, a write permission or an OIDC token runs (the scripts of the image publication, of the workshop's Discord jobs and of the dependency audit, the lock of the audit's tool), the canary, the CD of Imladris and what it installs, and `.github/`. Once the maintainer turns on « Require review from Code Owners » in the rule of `main` — after this merge, never before —, a pull request that touches one of them waits for his approval; every other one merges as before. `scripts/image_check.py`, which runs in the job that signs the images, no longer imports `scripts/component_check.py` (its list copied, kept equal by a test), so that a file most changes touch stays out of that job.
  - Tests: `tests/unit/test_codeowners.py` derives the list from each workflow job that holds a credential (its `run:` steps, local actions, sparse checkouts, installed locks, what a script imports or a shell script calls next to it) and from the CD's installed files, and fails on a file no line owns, on a line that owns none of them, or on a file next to such a script that would shadow the standard library (mutants M5741–M5751, `scripts/mutants/SEC-K.py`).
