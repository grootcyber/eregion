### Fixed
- **The tests of `make orodruin-update` and `make orodruin-check` no longer download cosign: the suite stays off the network, and they measure what they measured** (FLK6, #1252). The first release gate of 0.6.11 (shard 4/10 of the mutants) measured nothing: `test_the_update_s_ssh_takes_the_pinned_key_alone` failed on the code not mutated. Both recipes run `published_image.py install-cosign` first; under the test's throwaway HOME cosign was never there, so every run fetched it from GitHub, and a download that failed stopped `make` before the SSH calls the test waits for. What the two recipes run is now `ORO_COSIGN_INSTALL`: the real install by default, kept only if its sha256 is the pinned one, as before; replaced on the command line only, never by the environment. The tests replace it with a fake that records its call: the pinned key alone, no `accept-new`, the order of the SSH calls and the refusal without a fingerprint are measured as before, and the install asked for once, or never when the fingerprint is missing. Nothing is weakened for the operator: the comparison that follows uses the pinned cosign alone, and refuses without it. Measured in a network namespace of its own (`unshare -rn`): the 29 tests of the file pass, and none of the 154 files that run `make` or a script reaches GitHub any more. Mutants M8030–M8031.
  - Tests: `tests/unit/test_host_ssh.py`.
