### Security
- **The exercise windows, the signals `glorfindel respond` reads and a campaign's manifest are read through the bounded reader of `runs/`** (SEC-A1, #630; `docs/glorfindel.md`). `load_windows`, `close_window`, `glorfindel.signals.load_signals` and `CampaignManifest.load` now go through `eregion_core.channel_reader`: a regular file only, never through a link, never blocking, bounded in size (`WINDOW_BYTES` for a window, its mtime taken from the file read). At most `MAX_WINDOW_FILES` window files are read at a time; a JSON nested too deep is refused like any unreadable one. A refused file is said once and skipped, or the command stops with exit code 1; it is never waited on.
  - Tests: `tests/unit/test_bounded_reads.py`. Mutants M4520–M4522, M4564, M4566.
- **A local exercise window is bounded in the past by its file's mtime, and windows chained on one VM are bounded together** (SEC-A1, #630; `docs/glorfindel.md`, `docs/design/modele-de-menace.md`). A window written on the host (no `channel_created`, or in an injector's own directory, for the watch and the console alike) is refused when its last declared moment is more than `FUTURE_SKEW_S` before its file's mtime; at the watch, its record (SEC14) bounds it too. The windows on one VM cover at most `CHAIN_MAX_S` (8 h) of the `CHAIN_HORIZON_S` (24 h) before each one starts; a window past that bound no longer marks the VM (`chain_refusals`, computed once per VM). At the watch, the chain counts every window its record saw, its file deleted or not. A window the console refused attributes no cycle.
  - Tests: `tests/unit/test_bounded_reads.py`, `tests/unit/test_console_exercises.py`. Mutants M4523, M4524, M4563, M4565.
