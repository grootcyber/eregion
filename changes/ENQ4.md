### Added
- **The enquiry's loop, at the harness only: the model picks its reads, the code holds everything else** (ENQ4, #1085; `docs/raisonnement.md` §10.2, `docs/architecture.md`, « L'enquête, et son catalogue de lectures », `docs/operations.md`, « Le harnais de l'enquête » ; design: `docs/design/enquete-raisonnee.md` §5, §6.3, §14 question C). `glorfindel/enquiry/loop.py` is a plain Python loop, not a LangGraph subgraph (the maintainer's decision of 23/11, to be discussed again on the harness's measure): the model reads by id (`lire(id)`) in the closed catalogue, then ends (`conclure()`), both gestures of one tool, `enquete`. The code holds the budget N (4 reads chosen; past it, a read is never run) and the delay T (30 s for the whole enquiry, the model's turns included, a real delay on a monotonic clock: a read the code launched and T cut is a failure, a read asked once T is spent is not permitted, a model too slow ends the enquiry); runs the sheet's obligatory reads first, in parallel, outside N; permits only the sheet's reads the catalogue serves under the VM's system; fills the VM from the registry and each value from the detected line, checked by its parameter, never from the model; says a read announced but not yet in the catalogue « not served » and a read without object under the system « sans objet », never « empty »; checks every citation — a hypothesis of the sheet, a read of that hypothesis done today, a line actually shown (the proof kept is the row read, never the model's text) or an empty read for an absence, else unknown; a hypothesis with a predicate takes the code's verdict, and none is coded yet (its reads are not served).
  - Without a sheet, the base enquiry (today's routing on the detected line's columns) runs first, by the code, outside N. Only the reads the code asks itself — the obligatory ones, the base enquiry — make telemetry gaps: a read the model asked never does, whatever its state, and a read whose value the line does not give (a source address on a sudo line) is not offered; asked anyway, it is refused and noted. What today's decide then reads is only what the loop actually ran, never a read not served, which its message would say « no result ». One proof that does not hold makes its hypothesis unknown; what the model adds to its conclusion is ignored, and noted. No line break of any kind leaves a block of the message.
  - `glorfindel/enquiry/reference.py`: the enquiry's memory per object — the last enquiry on the same VM and the same rule (its date, its reads bounded, the decision, the human verdict), shown for 30 days, after the reads of the day. It never fills a read of today, never answers a citation, never closes a gap; « as usual » is received only on a human verdict « benign », never on a grave technique.
  - `glorfindel/enquiry/message.py`: what the loop's model sees — its own prompt, its tool, and each turn's message in the design's order (the detection, the sheet as the model may see it, the reads permitted and those not served, the reads done in labelled blocks of bounded lines, the last enquiry on the object, dated).
  - The harness gains the genre `enquete` (`scripts/harness_enquete.py`, `make llm-compare … ENQUETE=1`, `ENQ_N`, `ENQ_T`, `READ_DELAY`): the design's cases the catalogue can serve, on recorded reads, then today's decide on what the loop read; each turn of the loop is measured as an `enquiry` call by HRN1's meter (the latency of a turn). Never in the attestation.
  - Nothing the model sees in production changes: neither the graph, nor the watch, nor `investigate`, nor the CLI imports the loop (a test); the prompt, the user message, the few-shot examples and the decision tool are untouched, ENQ2's sha256 unchanged. No end-to-end run is required; the proof is the maintainer's harness session.
  - Tests: `tests/unit/test_enquiry_loop.py`, `tests/unit/test_harness_enquete.py`. Mutants M7123–M7132 (`scripts/mutants/ENQ4.py`).
