### Added
- **Who writes under Linux, by auditd: bounded write watches and their reader, declared to be measured at the bench** (WRT1, #1275; `docs/operations.md`, “Qui écrit sous Linux, par auditd (WRT1)”). PIO1's first bench session (27/11, #1258) found that `process.disk.io` sees only the agent's own collector; the cause, confirmed by the sources and not measured: it runs unprivileged, and Linux lets a process read `/proc/<pid>/io` only for its own processes, so `process_write_io` cannot say who writes under Linux.
  - The collection, off by default (`auditd_write_watch_enabled`, without effect unless `auditd_enabled`): the same CustomScript extension as AUD1 runs `infra/terraform/scripts/auditd_write.sh` after `scripts/auditd.sh` — write watches (`-a always,exit -F arch=b64|b32 -F dir=<folder> -F perm=w -k eregion_write`) on 1 to 8 bounded folders (`auditd_write_watch_dirs`; by default `/home`, `/root`, `/srv`, `/var/www`, `/var/backups`, `/mnt/testdata`; never `/proc`, `/sys`, `/dev`, `/run`, `/tmp`, `/var/tmp`, `/var/log`, `/var/opt`, `/var/spool`, `/var/cache` or `/var/lib/eregion` (the beat's), nothing below them, and no folder that holds one, such as `/var` or `/var/lib`: a watch is recursive), one event per opening for write, creation, rename, unlink or truncation, never per `write()`; and the watch's beat, a systemd timer writing every 5 minutes under a watch of its own (`eregion_write_beat`), its rules written last and every rule counted once loaded. The lines go to `Syslog` through AUD1's `local6`: the data collection rule is unchanged, no new right. Off, the extension's script is AUD1's, byte for byte. The same `make celebrimbor-auditd-plan` / `-up` targets.
  - The reader `process_write_audit` (`glorfindel/auditd_write.py`): one KQL query on `Syslog`, for a VM and the five minutes before the signal, through the caller's KQL runner (no SDK of its own); the executables that modified files, with their uid, login uid, number of processes, files and events, and a few paths kept as their folder and extension, never the file's name (a home folder's owner hidden). Without the beat on both sides of the window, “without object”, never “nothing written”; the paths column, which the SDK hands on as JSON text, read as such; a 403, a missing `Syslog` table, a failed query or an unreadable answer is a failure, said; an event with two SYSCALL records is never attributed; the Log Analytics read budget is taken first. The executable's path comes from the kernel, but the guest chooses where a binary lies: no hypothesis that relaxes leans on it.
  - Kept apart (`catalog.A_MESURER`, never `READS`): neither `investigate`, nor `decide`, nor the loop runs it, and nothing the model sees changes; `scripts/capture_enquete.py` reads it apart (`a_mesurer`), by the episode's own workspace.
  - Expected cost: about 3 KB billed per event, about 0.2 USD a month for the bench's two VMs (the beat, mostly), to be measured.
  - Tests: `tests/unit/test_auditd_write.py`, `infra/terraform/tests/auditd_write.tftest.hcl`.
