### Security
- **Every command to copy Glorfindel writes for a VM names it by `<group>/<name>`, which the CLI resolves — never its name alone** (MSK3b, #787; MSK3's follow-up; `docs/glorfindel.md`, « alerting webhook + bot Discord », `docs/operations.md`). Since MSK3 the bot's commands named the VM so, but the others still gave its short name: copied to another terminal (whose discovery may know only a homonym of another group), or on a subscription where two groups each hold a VM of that name, such a command could take the other VM, `--yes` asking nothing. Now the card « exécutée »'s undo (`glorfindel release rg-a/web --yes`, `glorfindel unblock <ip> rg-a/web --yes`), the TUI's lines (`restore`, `revert`), the console's 📋 Command (`restore`, `revert`, `activate`, the undo of an action taken alone, a held card's command), the watch's cards (a held snapshot's step, a prevented detection's `reset`, the reassertion's `release` / `unblock` — an interrupted lift, a vanished isolation or block, the TTL —, a recovery read on Azure's `restore` / `release`, a readiness card's `activate`; their full id, once masked, was no command at all) and the CLI's own hints (`list`, `jobs`, the steps of `pending`) name the VM by `<group>/<name>`, quoted for the shell when its group holds one of its characters. The CLI gives it only when it comes back to the same resource on its host; otherwise (a VM unknown here, one group and one name in two subscriptions, a NSG) it asks for the id, as MSK2 did — and two VMs of one name in two groups, which MSK2 could only send to the id, are each named by their own. The steps of a card written before (a short name, a full id) are said in that form by `pending`, as the bot did, masked by the subscriptions the step named as written and the card's id, learned before the rewriting takes the id away (`masking.shown`): a bare id of that subscription further on is masked too, whatever `AZURE_SUBSCRIPTION_ID` names. The form is written at the source (`glorfindel/vm_command.py`, which the graph and the watch import, never the display's masking; `glorfindel/masking.py` re-exports it): the card's `resource_id`, the signal and the journals keep the full id, the buttons act by it, and nothing the model sees changes. A guard reads the tree: a command to copy written in `glorfindel/` with a VM's id or its name alone fails it.
