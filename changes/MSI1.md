### Fixed
- **The control-plane warmup authenticates by the host's managed identity** (MSI1, part of #608). On an armed Orodruin the hardened container carries only the host's managed identity — no service-principal secret, no Azure CLI — so Terraform's `azurerm` provider, which the warmup runs, found no credential offline and failed. The adapter (`annatar/engines/stratus.py`, `azure_provider_env`) now hands the run `ARM_USE_MSI` with the subscription and the tenant (the IMDS token names neither), so the provider authenticates by that identity; the executor (`annatar/executors/stratus_host.py`) layers it over the inherited environment for every phase. When a service-principal secret IS present (a developer run with `.envrc` credentials) nothing is set — MSI is never forced over working credentials — and both the subscription and the tenant must be named, else the provider's own auth is left unchanged (a half-configured provider would fail less clearly).
  - Tests: `tests/unit/test_annatar_stratus.py` (MSI with only a managed identity; service-principal auth left untouched; nothing without both the subscription and the tenant; the directive reaches the warmup subprocess and is omitted under a secret). Mutants M6101 (the secret guard bypassed) + M6102 (`ARM_USE_MSI` never set) + M6103 (only one of subscription/tenant required) + M6104 (the executor drops the directive), `scripts/mutants/MSI1.py`.
