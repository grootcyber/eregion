### Fixed
- **The control-plane warmup authenticates by the host's managed identity** (MSI1, part of #608). On an armed Orodruin the hardened container carries only the host's system-assigned managed identity — no service-principal credential, no Azure CLI — so Terraform's `azurerm` provider, which the warmup runs, found no credential offline and failed. The adapter (`annatar/engines/stratus.py`, `azure_provider_env`) now hands the run `ARM_USE_MSI` with the subscription and the tenant (the IMDS token names neither), so the provider authenticates by that identity; the executor (`annatar/executors/stratus_host.py`) layers it over the inherited environment for every phase (warmup through cleanup). A service-principal credential in the environment — a client id, a secret, a certificate or a federated/OIDC token (a developer run with `.envrc`) — leaves the provider's own auth to resolve it; MSI is never forced over a configured credential. Blank values are treated as absent (whitespace is stripped, as the contract strips the tenant), and both the subscription and the tenant must be named, else the provider is left unchanged — a control-plane technique with no Graph probe that leaves `EREGION_TENANT_ID` unset names the tenant through `AZURE_TENANT_ID` (`infra/orodruin/orodruin.env.example`).
  - Tests: `tests/unit/test_annatar_stratus.py` (MSI with only a managed identity; every service-principal form left untouched; blank values ignored; the `AZURE_TENANT_ID` source; nothing without both the subscription and the tenant; the directive reaches the warmup subprocess and is omitted under a credential). Mutants M6101 (the credential guard bypassed), M6102 (`ARM_USE_MSI` never set), M6103 (only one of subscription/tenant required), M6104 (the executor drops the directive), M6105 (a blank value taken), M6106 (a blank credential blocks MSI), M6107 (a certificate SP not detected), M6108 (`AZURE_TENANT_ID` dropped as a source), `scripts/mutants/MSI1.py`.
