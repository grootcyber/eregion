### Fixed
- **An aggregated row whose gathered set grows keeps its identity, and makes no new card** (RID1, #1002; `docs/glorfindel.md`, « Déduplication »). A row without `TimeGenerated`, `EventId` or `CorrelationId` (`summarize … by Computer, SourceIP`) took into its identity every non-numeric text. The SDK hands a `dynamic` column (`make_set`, `make_list`, `pack`…) on as its JSON text (SLF1b): that text entered the identity, and a `make_set(User) by SourceIP` that grew made a new card at each value more. The tests passed Python lists, which never entered it. A text that decodes to a JSON array or object is now left out of the identity, read by `own_channel.json_of` (SLF1b's reading, now shared: bounded at 64 Ki characters, never raising); the grouping keys and every other text stay, a text unreadable or past the bound too. Only these rows dedupe differently: a client's rule or one the model wrote (`detection_authoring`) that gathers a set makes one card per group and window. Rows with an instant, Entra ID's rows and the control plane's are unchanged, and the identities of the 20 shipped rules are unchanged, frozen before and after on a representative row read through the SDK's own objects. A grouping key that is itself a JSON text (`by Props = tostring(pack(…))`) is left out too: no shipped rule has one.
