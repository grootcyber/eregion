### Fixed
- **The offline provider mirror now carries the providers the techniques use but do not declare** (R2BY, part of #608). A technique can use a Terraform provider (for example `random`, via a `random_password` resource) without listing it in `required_providers`; Terraform auto-resolves those from the registry, which the air-gapped execution host cannot reach — so the first real bench run failed with `provider … was not found in any of the search locations`. `scripts/stratus_build.py` now scans the azure techniques for every provider they use and stages those too (`implicit_providers`, pinned by `IMPLICIT_VERSIONS` and `annatar/stratus/PIN`, fail-closed: a used-but-unpinned provider refuses the build). At v2.38.1 the only one is `random`.
  - Tests: `tests/unit/test_stratus_build.py` (finds a used-undeclared provider, excludes declared ones, refuses an unpinned one, mirrors it). Mutants M6061 (implicit providers not staged) + M6062 (an unpinned one staged unverified), `scripts/mutants/R2BY.py`.
