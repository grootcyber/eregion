### Fixed
- **The invariant machine reads an isolation that recorded itself whole, then was cut off in its session drain, as superseding the release it replaces** (I9A, #823; `docs/design/preuves.md`). The deep night of 14/11 failed on « I9: the reassertion isolated …/web again mid-release », then every PR replayed it from the cached Hypothesis base. web's release had left its NIC in quarantine (its original NSG unknown); the operator isolated web again: nothing to write to Azure, the isolation rewrote its state whole, then crashed in its drain. Once the quarantine was taken off, the reassertion put it back, which was right: the operator's isolation is what holds. The test's journal ended a release only on an isolation that wrote to Azure. It now also ends it on one that wrote the VM's state, which the test sees through its own wrapper of the state writes, by the resource id each write carries. It never reads the code's marks (A0). An isolation cut off before writing anything still leaves the release under way, and I9 still holds it. The Azure and AWS machines read the journal the same way. The product is unchanged. The oracle's rule dates from A0 (13/10) and has been reachable since 27/10 (I8F): this was a new draw, not a regression.
