### Changed
- **The night runs on the subscription, the CLI's claude.ai login, never on an API key** (NOC1c, #1276; `docs/sessions.md`, « La nuit »). An `ANTHROPIC_API_KEY` set in the shell for Glorfindel passes before that login, and in `-p` the key is always used when present: the night would be billed on it, up to the pass's cap. The night's unit now carries `UnsetEnvironment=` with every source Claude Code ranks before the login (its documentation, « Authentication precedence »): `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, the cloud providers' `CLAUDE_CODE_USE_*`, and the Anthropic profile and federation variables, and `ANTHROPIC_BASE_URL`, which would route the pass's calls through a gateway the night never needs; `CLAUDE_CODE_OAUTH_TOKEN`, a subscription's token, stays. `install.sh` refuses a settings file the pass reads (`~/.claude/settings.json`, the repository's `.claude/settings.json` and `.claude/settings.local.json`) that sets one of those variables or an `apiKeyHelper`, naming the key, never its value; it refuses a `claude` taken from an editor's extension (`~/.vscode-server/extensions/`, `~/.vscode/extensions/`, `~/.cursor-server/extensions/`, or a link into one), whose path changes at each update of the extension, and says to install the CLI apart (`~/.local/bin/claude`). `DRY_RUN=1` shows the unset line and says each refusal without refusing. The unit's `PATH` names each directory once, `~/.local/bin` first. The documentation says how to check the login once by hand.
