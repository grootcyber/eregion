### Security
- **No message of the Discord bot nor of the webhook shows a subscription's id** (MSK3, #772; MSK2's follow-up, decided by Jonathan on 12/11: « as the CLI »; `docs/glorfindel.md`, « alerting webhook + bot Discord »). A message posted in a channel is pasted from it in an issue of the public repository: the bot and the webhook now say an ARM id by its resource's name and group (« vm-01 (groupe rg-a) ») and a subscription's id left bare by « <abonnement> » (`glorfindel/masking.py`), at the display only. The commands to copy of the 📋 Command button (`restore … --before`, `revert`, `activate`, and an action taken alone's `release` / `unblock`), and a card's steps that name its VM (written by the code with its id or its short name), name the VM by `<group>/<name>` (`glorfindel restore rg-a/vm-01 --yes --before …`): never its full id, never its name alone — the bot checks on its host, but the command is pasted on another (an operator's terminal, whose discovery may know only a homonym of another group, which a short name would have taken, `--yes` asking nothing). A VM whose id names no group: `<id: glorfindel list --ids>`. The card's embed masks the model's explanation, the reason, the suggested steps, the target (its name, its path, its limit), the evidence and the check of an action taken alone, an identity card's plan (its prose; a command of the plan that would name a subscription is not shown — the console's card holds it: a command is shown whole or not at all, never altered), the rule's name and the footer's run; a bare id of a subscription the card names anywhere, or the environment's, is masked in every text of it. The thread's name, its opening ping and `/pending` say a card filed on a subscription « <abonnement> », never its id; a thread opened before MSK3 and named by a subscription's id is renamed when it is used again (only then: a name an operator chose is kept). What a button says it ran (« ⚡ … → `glorfindel revert vm-01 --yes` », the restore's confirmation), the command's output, its error, the restore's form and its points (a vault's unreadable error names its scope), a verdict's error are masked too. The notices in the VM's thread (a cut's closure, an action's announcement) and the webhook's messages — the fallback when the bot is mute (Discord's endpoint and Slack's format), an escalation and an announcement without a bot (`escalations._notify`, its action, TTP and severity too; `_action_words`, masked first, then cut, and the text kept in the notices' store never cut inside a GUID) — as well.
  - What keeps the full id: the buttons' arguments (they act: `revert <id> --yes`, `restore <id> --yes --before …`), the escalations' store and the notices' (the text as written, masked where it is shown), the signals, the bot's and the watch's journals. The action queue's receipt (« File d'actions (<8 characters>) ») names the request, never a resource. What the model sees is never filtered: neither `_build_user_message()`, nor `_SYSTEM_PROMPT`, nor `few_shot_examples.yaml` changes; the guard of `tests/unit/test_cli_masking.py` now allows the CLI and the bot, and the masking of `vm_notices.py` and `escalations.py` inside their renderings only (`_short`, `_shown`; `_action_words`, `_notify`), never at a module's level.
  - **`<group>/<name>` in the CLI** (`_resolve_resource_id`): resolved on the host it runs on, from the active state and the discovery, the group and the name matching whatever their case; unknown there, refused (« inconnue de ce poste — glorfindel list --ids »), never passed to Azure as it is; one group and one name in two subscriptions, refused too. A full ARM id is taken as before, a short name as before (MSK2's own outputs keep it: same host, same registry). **The VM resolved is read back before anything is done, `--yes` too**: `restore`, `release`, `unblock` already said it (« Resource : »), `reset`, `revert` and `activate` now do (« VM : »); `snapshot`, which took its argument as an id, now resolves it too (a card's step `glorfindel snapshot <group>/<name> --yes` acts). Only a VM's own id (`…/virtualMachines/<name>`) is said `<group>/<name>`; a group holding a character the shell reads (« ( ) ») is quoted. A text is rewritten, then masked with the subscriptions learned from it as written (`masking.shown`, in the bot, the notices and both webhook renderings): a bare id of a subscription only a command's id named is masked too. The help of these commands says the three forms.
  - Known limits: the masking's own (MSK2: a few encodings of an id pass when nothing names its subscription); a host that knows, of that group and that name, only the VM of another subscription takes it (two subscriptions, one group, one name) — the line read back says it by its name and group, not by its subscription; and, in Azure's text, a principal's object id or a tenant's id, which nothing masks.
  - Tests: `tests/unit/test_bot_masking.py` (the review's case: the bot's command pasted where only the homonym is known, refused; `<group>/<name>` resolved, unknown, ambiguous, the full id; the VM read back with `--yes` by each command; a step's command; a thread renamed; the cut; each path: the commands, the homonym, the buttons keeping the id, the embed and the store, an executed card's evidence, an identity plan's command held, a card filed on a subscription, a button's run and its error, a restore's confirmation and form, the notices and the store keeping their text, the fallback on both webhooks, an escalation and an announcement by the webhook).
