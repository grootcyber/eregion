### Security
- **No message of the Discord bot nor of the webhook shows a subscription's id** (MSK3, #772; MSK2's follow-up, decided by Jonathan on 12/11: « as the CLI »; `docs/glorfindel.md`, « alerting webhook + bot Discord »). A message posted in a channel is pasted from it in an issue of the public repository: the bot and the webhook now say an ARM id by its resource's name and group (« vm-01 (groupe rg-a) ») and a subscription's id left bare by « <abonnement> » (`glorfindel/masking.py`), at the display only. The commands to copy of the 📋 Command button (`restore … --before`, `revert`, `activate`, and an action taken alone's `release` / `unblock`) name the VM by the CLI's rule (`_name_for_a_command`): its short name when every command takes it back to that very VM, otherwise `<id: glorfindel list --ids>` — never a homonym of another group. The card's embed masks the model's explanation, the reason, the suggested steps, the target (its name, its path, its limit), the evidence and the check of an action taken alone, an identity card's plan (its prose; a command of the plan that would name a subscription is not shown — the console's card holds it: a command is shown whole or not at all, never altered), the rule's name and the footer's run; a bare id of a subscription the card names anywhere, or the environment's, is masked in every text of it. The thread's name, its opening ping and `/pending` say a card filed on a subscription « <abonnement> », never its id. What a button says it ran (« ⚡ … → `glorfindel revert vm-01 --yes` », the restore's confirmation), the command's output, its error, the restore's form and its points (a vault's unreadable error names its scope), a verdict's error are masked too. The notices in the VM's thread (a cut's closure, an action's announcement) and the webhook's messages — the fallback when the bot is mute (Discord's endpoint and Slack's format), an escalation and an announcement without a bot (`escalations._notify`, `_action_words`) — as well.
  - What keeps the full id: the buttons' arguments (they act: `revert <id> --yes`, `restore <id> --yes --before …`), the escalations' store and the notices' (the text as written, masked where it is shown), the signals, the bot's and the watch's journals. The action queue's receipt (« File d'actions (<8 characters>) ») names the request, never a resource. What the model sees is never filtered: neither `_build_user_message()`, nor `_SYSTEM_PROMPT`, nor `few_shot_examples.yaml` changes; the guard of `tests/unit/test_cli_masking.py` now allows the CLI and the bot, and the masking of `vm_notices.py` and `escalations.py` inside their renderings only (`_short`, `_shown`; `_action_words`, `_notify`), never at a module's level.
  - Known limits: the masking's own (MSK2: a few encodings of an id pass when nothing names its subscription); a name chosen when the message is posted (a command read much later may meet a registry that changed — run `glorfindel list` again); and, in Azure's text, a principal's object id or a tenant's id, which nothing masks.
  - Tests: `tests/unit/test_bot_masking.py` (each path: the commands, the homonym, the buttons keeping the id, the embed and the store, an executed card's evidence, an identity plan's command held, a card filed on a subscription, a button's run and its error, a restore's confirmation and form, the notices and the store keeping their text, the fallback on both webhooks, an escalation and an announcement by the webhook). Mutants M5020–M5029.
