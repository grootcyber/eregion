### Changed
- **The NSG audit reads the addresses of a VM without NSG, and still fails it; a public IP that does not read carries its code** (IPS2a, part of #950; `docs/azure.md`, « L'IP publique de chaque carte, dans l'audit »). A VM with a network interface that has no NSG, neither its own nor its subnet's, made `check_nsg_access` fail before any address was read, though it is the most exposed case. The « NSG access » check now stays `fail`, with the same reason and fix as before, and carries `data.nsgs[]`, one entry per network interface: `nsg_scope: "none"` and `nsg: ""` (empty, never absent) for one without NSG, the rest as before, `ips` and `public_ips` for each. An element of `public_ips` whose read failed carries `code` (`forbidden`, `not_found`, `not_allocated`, `unreadable`) beside `error`, its French text, unchanged; a read address has no code. Nothing else changes in the shape rendered. A failure that carries data stays a failure for every reader: the audit's verdict (`ready` false, as the console's `/api/audit`, the watch's startup audit and `glorfindel audit` read it), the readiness (the `no_nsg_for_blocks` reserve, so the autonomy gate of `decide` keeps the VM in `human_only` until it is confirmed, and the bot's card), the posture (the critical `nsg_reachable` gap); none takes `data.nsgs` for an NSG that reads, nor for an isolation or a block that is possible. The check is never a transient warn nor an IAM fix, whatever the interface's name; an interface whose subnet does not read is not said without NSG, its failure as before, without data. Read-only, no right added.
  - Tests: `tests/unit/test_audit_no_nsg.py`, `tests/unit/test_public_ips.py`. Mutants M6511–M6520 (`scripts/mutants/IPS2a.py`); the anchors of M6424 and M6425 (`scripts/mutants/IPS1a.py`) follow the element's new code.
