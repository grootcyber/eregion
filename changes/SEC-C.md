### Security
- **Imladris's checkout fetches from the repository's current name, and its deployment by hand is verified like the CD's** (SEC-C, #635; audit of 06/11, V-29; `infra/glorfindel-host/README.md`, « Ce que la VM exécute »). `deploy.sh` (by hand, and the CD's switch) and the CD point `origin` at the current name before every fetch, and say it when it changes; `eregion_repo` keeps the former one until the next rebuild of Imladris (it only serves the clone). `make imladris-start REF=…` now proves REF on the workstation first — its commit on `origin/main`, the signature and the provenance of the image the CI published for it, with the pinned cosign (`scripts/published_image.py proven`) — and hands the VM that commit, never a name to resolve there: the VM refuses a REF that resolves to another commit. A reference without a verified published image is refused, with no gesture to bypass it. `--build-only` and `--activate` are unchanged but for the origin. Reinstall the CD's agent (`make imladris-cd-install`) for it to point its origin.
  - Tests: `tests/unit/test_host_deploy.py`, `tests/unit/test_host_cd.py`, `tests/unit/test_published_image.py`, `tests/unit/test_repo_owner.py`.
- **Orodruin's update has a floor** (SEC-C, #635; audit of 06/11, V-24; `infra/orodruin/README.md`, « Le plancher, le retour arrière »). `make orodruin-push` and `make orodruin-update` refuse a release older than the highest already pushed and verified — the image in service on Orodruin (its `~/.eregion-image`, read first) and this workstation's memory (`~/.eregion/orodruin_floor.json`, raised after each push, never lowered), which still holds for a rebuilt Orodruin — unless the way back is asked, `ROLLBACK=1` with `REF` on the command line, said in the output. Without REF, the release taken is the highest whose published image is verified, never a local tag believed on its name; a higher one without a signed image is set aside and said.
  - Tests: `tests/unit/test_published_image.py`.
- **Imladris's host key fingerprint is required** (SEC-C, #635; audit of 06/11, V-26; `infra/glorfindel-host/README.md`, « SSH »). Without `HOST_SSH_FINGERPRINT`, no command reaches Imladris any more, the `scp` of `host.env` included — never `accept-new`, as for Orodruin. `make imladris-fingerprint` reads the ED25519 fingerprint on the VM through Azure's control plane (Run Command), never through SSH, and prints the `export` line to set. Imladris's CD runs on the VM and does not read it: a pass in progress is never cut. Set it before any `imladris-*` command after this release.
  - Tests: `tests/unit/test_host_ssh.py` (mutants M5446–M5463, `scripts/mutants/SEC-C.py`).
