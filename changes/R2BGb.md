### Security
- **An Orodruin apply no longer destroys the Stratus guardrails by omission** (R2BGb, #897). The dedicated test subscription's guardrails — the budget, the activity-log diagnostic to the bench workspace (what the detection reads), and the Azure Policy limits on regions / resource types / VM SKUs and a public IP on a NIC — exist in Terraform only while `stratus_guardrails_enabled` is true and the `stratus_*` vars are passed; an apply run without them saw `count = 0` and tore them down silently. Those vars now live in `infra/orodruin/stratus.auto.tfvars` (Terraform loads every `*.auto.tfvars` itself on each plan, like `session_drain.auto.tfvars`), so they are always passed — with a committed `stratus.auto.tfvars.example`. As a backstop, `scripts/stratus_guard.py` runs before `orodruin-plan`/`-up`/`-lock` (never `-down`, a deliberate teardown): if the Terraform state holds Stratus guardrail resources but the flag is off, it refuses before the plan, so the guardrails are never wiped by omission; an intentional removal sets `STRATUS_GUARD_ACK=1`.
The effective flag follows Terraform's own precedence (the `*.auto.tfvars` wins over `TF_VAR_*`), so a file saying `false` with the env saying `true` reads off — the guard refuses rather than letting the destruction through.
  - Tests: `tests/unit/test_stratus_guard.py` (each guardrail resource is detected and the inert `terraform_data.stratus_guard` is not; refuse when the state is guarded and the flag off, allow when on or when nothing is guarded; the auto.tfvars wins over the env; `main` returns a failing code when it refuses and the ack bypasses it; the example's values pass `variables.tf`'s validations; the guard wired on the three converging applies and absent on the destroy).
