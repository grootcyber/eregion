### Changed
- **The design of the isolation dossier records the operator's decisions of 23/11** (DOS3b, #1063; `docs/design/dossier-isolation.md` §4.6, §11, §12; `docs/glorfindel.md`, « Le dossier d'une isolation »). No code changes.
  - A block executed alone has no dossier: its card, its reasoning and its decision line already say why. The exception first asked for an internal address never arises for a private address: the never-block list never lets one be blocked, whatever the provider, and lateral movement is answered by isolating the source VM. An address of a client network outside the private ranges can be blocked today, with no dossier: the never-block list does not know those networks unless the operator lists them in `never_block` (`docs/operations.md`). The exception would first need the discovery to keep the client's networks; the code written for it covered only the private ranges, for want of the networks in the discovery, and was removed on the operator's decision.
  - A detection with no attributed VM keeps its local dossier of step 0; the reads of Azure (DOS4) will never be made for it, and its dossier will say so.
  - The hourly ceiling of dossiers is to be asked again when DOS4 is framed, with the proposal written in the design.
  - An open point is given to DOS4: a proposed block approved later (console, bot, signed queue) has its dossier's clock started at the first pass, and the dossier goes 30 days later even while the block holds.
