### Security
- **Both images install `zlib1g` at its fixed version, the one written and dated exception to « no `apt-get upgrade` »** (ZLIB1, #962; `docs/operations.md`, « Les images publiées »). The base `python:3.12-slim`, pinned by its digest, carries `zlib1g` `1:1.3.dfsg+really1.3.1-1+b1`, with CVE-2026-85091 (High), fixed upstream in `1:1.3.dfsg+really1.3.1-1+deb13u1` (DSA-6613-1, trixie-security); no digest of the base carried the fix yet, so the release gate refused both images. `glorfindel/Dockerfile` and `annatar/Dockerfile` now install that exact version, in one layer right after `FROM`, as root, byte for byte the same in both: never an upgrade, never a free version. If Debian replaces that version, the build breaks loudly, on purpose. The layer is removed in the pull request of the base's bump whose digest carries `+deb13u1` or newer. The release gate is unchanged and as strict: both images, built and scanned, show no High or Critical CVE fixed upstream in their system packages.
  - Tests: `tests/unit/test_image_cves.py` (the same exception in both Dockerfiles, the exact version, before any `USER`, no `apt-get install` without a version, its reason and its removal said; the version read in images already built when `EREGION_ZLIB1_IMAGES` names them); mutants M6626–M6635 (`scripts/mutants/ZLIB1.py`).
