### Added
- **The section `assets:` in `glorfindel-config.yaml`: each VM or pattern with a mode, a priority, or both** (PRI2a, #1219; `docs/design/classification.md`, `docs/operations.md`, « Configuration »). `assets:` (`default_mode`, `allow_destructive`, `list` of entries `match`, `mode`, `priority`, `reason`) replaces `autonomy:`. The priority is `essential`, `standard` (the default) or `quiet`, and sets what Glorfindel spends on a VM and its rank in the queues of the calls to the model, never what it detects, decides or does alone: `essential` keeps PRT2's reserve of the model's budget for its grave detections, and `quiet` is a label for now, with `standard`'s budget. Each field resolves on its own, the exact entry first and then the longest pattern, among the entries that carry it; tied, the most prudent mode and the highest level. An entry with no mode never changes a VM's mode. The strict reading refuses an entry that says nothing, the same `match` twice (case ignored), an unknown priority, any other key, and both formats in one file. The former format `autonomy:` (with `critical: true` read as `priority: essential`) is still read until 1.0, in the same model, with a note at the watch's start and in `/api/config` (`assets_format`, `assets_notes`): « autonomy: is the former format of assets: — migrate it (glorfindel config migrate) ». The persisted buckets `real/critical` and `real/noncritical` keep their names, so the day's count survives the update.
  - Tests: `tests/unit/test_config_assets.py`, `tests/unit/test_relaxed_view.py`, `tests/unit/test_config.py`.
- **`glorfindel config migrate`** (PRI2a). The command writes the former format as `assets:`, at equal values, through CFG4's writer: it keeps the round trip and the file's lock, shows the change and its notes (duplicates merged into one entry with the most prudent mode and the highest priority, each `critical: true`), and refuses any migration CFG4 would not class neutral. `--to autonomy` converts back, for a rollback to a release that does not read `assets:`. It never writes a bolder mode: an `essential` entry without a mode gets the mode its VM has, `human_only` for a pattern. `quiet`, `standard` and `reason` are dropped, and the command says so. A migrated file must not be pushed to Imladris until the push reads `assets:` (PRI2b, in the same release), and the command says that too.
  - Tests: `tests/unit/test_config_assets.py`.
- **PR1's guard of structure** (PRI2a). Only a closed list of modules reads a VM's priority (`level_of`, `is_critical`, `critical_count`): the model's budget, the gate of the calls, the class of a change, the view « Relaxed », the console, the watch's start, the config's reading and writers. `decide` and the bot never read a `priority` the data carries.
  - Tests: `tests/unit/test_priority_boundary.py`.

### Changed
- **The class of a change (CFG4) is computed on the model read, name by name** (PRI2a). `_critical`, which compared the entries saying `critical: true`, gives way to the level `level_of` gives each name or pattern cited. Up tightens and down relaxes, `standard` → `quiet` included by prudence. A pattern carrying a priority whose text changes relaxes, and so does one essential entry fewer, because the reserve is counted by entry. `allow_destructive` is compared on the model, never at its former path. A section of the strict reading that no function classes relaxes when it changes. The migration is neutral. Each writer keeps the file's format: the console's mode selector, the default and the CLI write `assets.list` in a file in `assets:` and `autonomy.assets` in the former format, and none migrates in silence. The view « Relaxed » reads both formats and gives each `quiet` entry its line. `glorfindel-config.yaml.example` is written in `assets:`.
  - Tests: `tests/unit/test_config_assets.py`, `tests/unit/test_config_edit.py`, `tests/unit/test_relaxed_view.py`, mutants M7789–M7805 and M7821–M7826 (`scripts/mutants/PRI2a.py`); PRT2's M7427 and M7428, CFG4's M7285 and AUC's M3180 and M3181 re-anchored.
