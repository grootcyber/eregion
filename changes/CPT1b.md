### Fixed
- **A control-plane summary card names the caller and the resource of each operation, as that operation's own card does** (CPT1b, #940; `docs/glorfindel.md`, control plane). Past 5 operations in one poll (SEC2, an infrastructure set-up exceeds it), the summary card kept each operation's `Caller` alone and printed « ? » when it was empty, where the individual card names the object id or the application id the rules draw from `Claims` (CPT1). Each operation is now read by the individual card's readings: the caller by `Caller`, else the name `Claims` gives, else the object id, else the application; the resource by `_ResourceId`, else `ResourceId`. A true void still reads « appelant inconnu », nothing made up; a summary written before reads as it did. The shipped queries never give a row without its `OperationNameValue` (tested).
- **The limits CPT1's review left** (CPT1b, #940). « Télémétrie incomplète … Sévérité moindre » is written only on a card really lowered, never on a signal that came `critical`; `Claims` names the caller by the long URIs of `upn` and `name` too, and the card names them; the doc says a row that carries the caller's address alone is lowered; the console's feed says « control plane, incomplete telemetry (detection only) ».
