### Added
- **Two operations of Azure's control plane detected and escalated: a Run Command on a VM by a caller other than Glorfindel, and a Bastion shareable link** (AL3, #867 ; `docs/glorfindel.md`, `docs/design/stratus-cible.md`). Two shipped rules on the Activity Log, in the base, decided by the code, no model, no action: `run-command-by-external-caller` (T1651) and `bastion-shareable-link-created` (T1133), on the shape their lines had on the bench on 17/11. Every operation is read, the refused ones too, and the card says when an operation only failed: a departure from the family, whose rules set an operation that only failed aside, said in both rules. No identity is excluded: every external caller is escalated, to be refined on the first real reading. Glorfindel's own session drain is a card of no Run Command rule: the external rule sets every row under its identity aside (its command outside a drain stays the critical card of `run-command-by-glorfindel-outside-isolation`, once), a client's rule on Run Command attaches it to its drain as before. A row that names no caller, or read while Glorfindel's identity is unknown, stays.
  - Tests: `tests/unit/test_run_command_callers.py` (the queries as written, over lines of the measured shape; the real detector, RulePoller, decision and graph); mutants M5501–M5519, `scripts/mutants/AL3.py`.

### Fixed
- **A control-plane row on a VM the discovery does not know is a card on its group, no longer dropped unsaid** (AL3, #867 ; `docs/glorfindel.md`). A Run Command on a VM of another subscription, a role on a VM evicted or not yet discovered: the RulePoller dropped the row, the rule matching or not. It is now a card, unattributed, filed on the VM's resource group, its resource id as read, the limit said, never an action. A VM the discovery knows and the rule does not watch (excluded from it, another backend's) stays dropped, as does a row of a rule bound to one asset.
  - Tests: `tests/unit/test_run_command_callers.py`, `tests/unit/test_card_target.py`.
