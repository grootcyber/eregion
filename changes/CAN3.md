### Changed
- **The azurerm canary's OIDC sign-ins no longer make an `entra-sp-unusual-signin` card on the bench** (CAN3, #673 ; `docs/glorfindel.md`, « Les connexions OIDC du canari azurerm » ; `infra/glorfindel-host/README.md`, « Les connexions OIDC du canari (CAN3) »). The canary (`.github/workflows/canary-azurerm.yml`, no secret) signs in from GitHub's hosted runners, whose address changes every run: the shipped rule, a principal's sign-in from an address never seen in 14 days, made a card at every run on H0. Jonathan's decision (09/11): in the bench's client layer (`infra/glorfindel-host/client_rules.bench.yaml`), the shipped rule copied as it is (`base_sha256`) plus one exclusion, read on each sign-in line before the lines are grouped by principal and address, the 14-day baseline untouched. A line is set aside only when both hold: its client application is the canary's — the appid taken from the watch's environment by `env_guids: [EREGION_RULE_CANARY_APPID]`, CAN2's variable, already on H0, never in the repository — and it was made with a federated identity credential (`ClientCredentialType =~ "federatedIdentityCredential"`, Microsoft Graph's value, and `FederatedCredentialId` not empty). The canary's principal by a secret, a certificate or a bare assertion, and any other principal, still make a card; the variable absent or not a GUID, the copy is set aside and the shipped rule runs, said. No code: `env_guids` (0.5.8) is enough, and the copy reaches H0 by `make glorfindel-host-client-rules`, without a release. To measure on the bench at the canary's next run: the form the workspace writes in `ClientCredentialType`, and that `FederatedCredentialId` is filled — another form keeps the cards (nothing hidden) and is fixed in the copy. Limits: any federated credential of the canary's application is read as the canary's (adding one makes an `entra-credential-added` card, not set aside); the principal is known by its appid, not its object id.
  - Tests : `tests/unit/test_canary_signin.py` (the shipped rule and its copy run as written on lines in `AADServicePrincipalSignInLogs`' form, then through the RulePoller and the Entra adapter); `tests/unit/kql_subset.py` now reads `let`, `join kind=inner|leftanti`, `distinct`, `between`, `dcount`, `make_set`, `bin`, `strcat_array` and `project X = …`.
