### Fixed
- **The drill's Logic App starts at an hour that ends in `Z`, the form Azure requires in time zone UTC** (DRL1f, #963, part of #613; `docs/design/drill-banc.md` §14). DRL1c's template gave the weekly Recurrence `"startTime": "2026-01-01T00:00:00"`, without an offset, beside `timeZone: UTC`; at the apply, Azure refused the template (`InvalidWorkflowTriggerRecurrence: … invalid start time '2026-01-01T00:00:00.0000000' zone designator for time zone 'UTC'. Expected … 'yyyy-MM-ddTHH:mm:ssZ'`, read on the bench on 20/11), so `make orodruin-up` and `make orodruin-lock` failed on main. This is Azure's actual answer, which wins over its documentation where it says the opposite for a named time zone. The template now says `"startTime": "2026-01-01T00:00:00Z"`; nothing else changes (`state: Disabled`, `timeZone: UTC`, the schedule), and the drill's reader (`drill_ops.autostart_at`, which does not read `startTime`) still reads it. The mock providers of `terraform test` deploy nothing and never saw it: a unit test now reads the filled template and requires, of every Recurrence in UTC, a `startTime` of the form `yyyy-MM-ddTHH:mm:ssZ`, and the planned test checks the same format.
