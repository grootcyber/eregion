### Changed
- **`make imladris-push` reads `assets:` as the watch reads it, writes the format Imladris's release reads, and never lowers a level** (PRI2b, #1225; `infra/glorfindel-host/README.md`, `docs/operations.md`, « Configuration », `docs/design/classification.md` §5.5). The push's reader (`infra/glorfindel-host/host_config.py`, which imports nothing of Glorfindel) now takes `assets:` and the former `autonomy:` with the watch's keys, modes, priorities and refusals: both formats in one file, the same `match` twice, an entry that says nothing, an unknown priority, a reason that is not one line. A config of Imladris the watch would refuse keeps nothing, so every VM goes to `human_only`, as before; it also closes two holes of the former reader, `autonomy.assets: {}` and `allow_destructive` written as a text. A file of the workstation the watch would refuse is never pushed: the push stops and says so, unless `HUMAN_ONLY=1`, which carries none of its entries. A workstation's file that is absent, empty, not UTF-8 or not a YAML table stops the push, `HUMAN_ONLY=1` included, since an empty config pushed would take Imladris's backends, exceptions and isolation away. Before, a workstation's file in `assets:` was copied beside a new `autonomy:` section, and Imladris's watch refused the whole file.
  - **The version guard.** The push reads the `org.opencontainers.image.version` label of each container that mounts the config, the label the CD reads, through the ssh it already opens, and reads it again before the `scp`. It writes `assets:` only when the watch is read and every container runs `v0.6.10` or later. A release before, or one that cannot be read (a container removed, a commit deployed by hand, no label), receives the former format, converted as `glorfindel config migrate --to autonomy` converts, never with a bolder mode. An Imladris in `assets:` its watch would read keeps its levels there, written `critical: true`, never its modes, and the report names each `essential` kept or lost. A stopped container keeps its label: one left from an older release (an `eregion-restore` never recreated) makes the push write the former format until it is removed, and the report names it. Neither this read nor a section of the workstation the watch would refuse ever blocks `HUMAN_ONLY=1`; a workstation's file that cannot be read does.
  - **The migration at the push, and the way back.** An Imladris still in `autonomy:` is migrated to `assets:` by the push, at equal values, and the report says so. `make imladris-push IMLADRIS_CONFIG_FORMAT=autonomy` writes the former format whatever runs: the way back to a release that does not read `assets:`, done from the workstation before the rollback. The variable is heard on the command line only, and refused when it comes from the environment, like `REF` and `ROLLBACK`.
  - **Never a level lowered.** Every level of Imladris is kept, its patterns and its `quiet` included: `quiet` comes from Imladris only, posed by hand on the host. A workstation's level is pushed only when it lowers no name nor pattern cited in either config (« lowers vm-erp-qa on Imladris: not pushed »). A workstation's `quiet` is never pushed, nor a workstation's pattern that says `standard`, which could lower a VM no name shows. An entry that carries only a level goes without a mode. Each VM's mode is kept as before, never a bolder one.
  - **The report tells the truth.** It is read name by name on the config written, as Imladris's watch will read it, with each mode, each level and where they come from, in English.
  - Tests: `tests/unit/test_host_config_assets.py` (PR4 and PR5 as properties, the watch's own reading as the oracle), `tests/unit/test_glorfindel_host.py`, `tests/unit/test_host_console.py`, `tests/unit/test_console_rotate.py`; mutants M7827–M7840 and M7861–M7865 (`scripts/mutants/PRI2b.py`); ten of BL1c's mutants re-anchored on the new reader, their sense unchanged: M54, M2363–M2366, M2368, M2369, M2781, M2782 and M2784.
