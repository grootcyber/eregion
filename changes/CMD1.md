### Added
- **`glorfindel isolate <group>/<name>` and `glorfindel block <ip> <group>/<name> [--scope vm|subnet]`: a containment by a human's hand, with `--dry-run` and `--yes` as `release` and `unblock`** (CMD1, #797; Jonathan's decision of 13/11; `README.md`, « CLI reference », `docs/operations.md`, `docs/design/file-actions-signee.md` §2.12, `docs/design/modele-de-menace.md` §2). The console's command for a held card and the reassertion's card for a NIC a perimeter block does not cover proposed them; the CLI had neither. They are the console's approval of a held card, without the card, from a terminal — the console closed (the workstation's shell, the phone's, MOB1), or no card at all — and they go through the same calls and the same guards, shared in `glorfindel/gestures.py` (`direct_refusal`, `address_refusal`, `contain`), before any call to the cloud: the VM resolved as `release` resolves it (`<group>/<name>`, MSK3b) and said before anything is done; one host address (`single_host_ip`), never one of the never-block list (SEC2); a VM of the watch's perimeter (discovered, held, or of a pending card), never another resource; never a VM a pending card is only anchored on (AL1: read the card, acknowledge it, act on the VM it is about); credentials that can write (`GLORFINDEL_READ_ONLY`, refused before the prompt). Then, under the VM's lock for the whole gesture, the connector's own write — its state written where the watch writes it, so the reassertion rereads it and `release` / `unblock` lift it — and the console's check after (`approval.verify_approved`): a `verification_failed` card when it is not `True`, said, exit code 2 — so too for a write that lands on some NICs only (`PartialActionError`: what landed kept, the NIC that failed named), and for a session cut still running with no live watch on the host to reread it (not verified: cut the sessions by hand). The gesture is noted in `runs/console` where the CLI can write it; in the watch's container that directory is mounted read-only — not noted there, said once, as for `release` and `unblock`. `--dry-run` checks the guards only, read-only credentials included. A pending card of the same VM and action is said, never resolved: the human acknowledges it. The state is the host's `~/.glorfindel`: with no live watch on the host (a workstation while the watch runs on Imladris), the CLI says that a watch of another host will not reread it, and to run the gesture in the watch's container there (`docker exec -it eregion-watch glorfindel …`: without `-it` the prompt reads an end of file). The VM's lock is the host's: a workstation and Imladris share none, and the CLI waits for it unbounded, in silence, behind a write that may last (a session cut, about 300 s). Whether a gesture by hand should be refused, or only said, by the target's enrollment zone is left to Jonathan's decision: none is refused today.
