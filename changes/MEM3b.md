### Fixed
- **The analysis index never opens a file of ChromaDB as its table, and the note on the old index is silenced only by the import of that index** (MEM3b, #1052; `docs/analysis.md`, « L'index sur une table, sans ChromaDB »). Four findings of MEM3's review, fixed before the old index is imported on Imladris and before MEM4.
  - A file of ChromaDB named as the index (`EREGION_ANALYSIS_INDEX` on a `chroma.sqlite3`: the old index's own, or a copy of Glorfindel's memory of today) is refused at its opening, before anything is written but the rollback of a hot journal, and said with the setting to change: never read as an empty index, the table and the imports never created in it. Before, only Glorfindel's memory in the form MEM2 will give it (its table `cycles`) was refused. Both are now seen by a read-only connection before the one that writes: a hot copy in WAL, with its `-wal`, is never checkpointed into its file. A table of the analysis left with a hot journal (a writer killed in a transaction) is read as its file lies, then opened to write, which rolls the journal back: its committed rows come back; on a file of ChromaDB or of Glorfindel's memory with a hot journal, the tables are read again in the connection that writes, once it has rolled the journal back (a view as the file lies may hold uncommitted pages): that rollback, which gives the file back its committed state as any reader of SQLite would, is the only write, then the refusal.
  - The import of the old index refuses a temporary directory inside the copy it reads (`tempfile.tempdir`, `TMPDIR`, `TEMP`, `TMP`, resolved) before anything else: before `gettempdir()`, which writes a probe file in the first candidate that works, and before its working folder is made. Nothing is created in that copy, not even for a while. Before, the folder was made, then refused.
  - The import records the path it read, resolved, and the report's note (« Index vide ou non importé ») is silenced only by the import of the old index beside the table (`..` and links resolved): the import of another copy, or rows a report wrote, no longer silence it. An import recorded before, under a relative path, is silenced by importing again: the import is idempotent. The comparison does not fold case, on a case-insensitive file system.
  - Said in `docs/analysis.md`, beside the 50 rows `prior_runs` reads: rows a report wrote before the import come before the old index's, which the import puts at the end — import the old index before the first campaign reported after MEM3.
  - Tests: `tests/unit/test_analysis_index.py`. Mutants M7071–M7074 (`scripts/mutants/MEM3b.py`).
