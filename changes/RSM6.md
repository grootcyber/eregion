### Fixed
- **The reassertion keeps the promise its card makes for a deferred perimeter pair** (RSM6, #1263; `docs/design/reaffirmation.md` §3.1 R3, §3.6). A perimeter block alone, its pair gone, the subnet's NSG unread at the write (a 429): every write failed, and the card said the pair would be put back « once, at the next pass if the read allows » — but the deferral was marked only where something had been written, so the next pass read the drift « already said » and stayed silent, the pair gone until a restart. The deferral is now marked when nothing was written too, and, by the maintainer's decision of 27/11, it holds as long as the cause is a read refused: one read a pass, nothing written while where the pair would land is unknown, the VM's rules never written again meanwhile, the same card brought up to date (never a new one a pass); once the read passes, the pair is put back once, on its own NSG only, never in `human_only`. A merged entry whose VM rules failed as well gets them back with the pair, once, as nothing was spent. Another cause of failure at that try (the write refused, another NSG) still spends it. RSM3's guards are kept (`_pair_not_home`, `refused_elsewhere`, one put-back per hold). The card of a failed put-back ends with its full stop (« … — rien n'est posé. Sa règle de périmètre … »).
- **The card of a VM the reassertion skipped closes when it should** (RSM6, #1263; `docs/design/reaffirmation.md` §3.2). The card `reassert-busy-…` closed only in the process that counted the skips: after a restart it stayed pending, and so did the card of a VM lifted or unblocked while it was skipped. It now closes at the end of the first pass that reads the VM, after a restart too, or once the VM is no longer recorded — read from the recorded isolations and blocks, never from a VM merely not read (a lock that raises an OSError keeps the card), and not while a state file cannot be read; never while the VM is still skipped. The cards are read from the store at the end of the pass, so a card the operator acknowledged during the pass is never closed again. A run of skips the pass does not continue is over, so a VM isolated again later counts from one.
