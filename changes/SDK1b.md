### Added
- **The ten `azure.mgmt` operations Glorfindel's adapters read most, tested on the pinned SDKs' own objects** (SDK1b, #1017; `docs/design/preuves.md`, `docs/azure.md`). The NSG and network interface listings of each pass of the watch, the VM, its network interface, its subnet, its NSG and its rules (each verification, each action, the posture), the vault's jobs, a job's details and a VM's recovery points: each body goes through the SDK's own client (azure-mgmt-network 33.1, azure-mgmt-compute 39, azure-mgmt-recoveryservicesbackup 11.2), its pipeline, its pager and its errors, then through the adapter's code. Only the socket is replaced (`tests/unit/sdk_mgmt.py`, an in-memory ARM that refuses any write). Enums stay enums, absent fields come out `None`, and a polymorphic `properties` is the class its discriminator names.
  - The pinned versions are generated from TypeSpec and have no `Model.deserialize()`: each operation reads its reply with `_deserialize(Model, body)`, and the tests take that path.
  - The bodies (`tests/unit/sdk_bodies/`) are hypotheses for now: the shape of the REST reference's sample for the API version the SDK sends, with made-up values for the bench at rest. Every `azure.mgmt` call of the adapters is inventoried, with how often it is read, and a new one fails the test until it is placed.
- **A read-only capture of those bodies at the bench, for the maintainer** (SDK1b, #1017). `scripts/sdk_capture.py` reads only a closed list of `get` and `list` operations, on a transport that refuses any method but GET before it leaves, as the maintainer's `az login` identity. It keeps each raw body as the API sent it.
  - Before anything is written, it anonymizes GUIDs, names, the marks Glorfindel's rule names end with, private and public addresses, MACs, e-mail addresses, free text and secrets, the same real value always getting the same stand-in and ARM ids keeping their shape. A check then refuses to write if a real value it met remains, or if a value is not of a stand-in's form. `check` runs that check again on a folder.
  - No session runs the capture.
  - Tests: `tests/unit/test_sdk_mgmt_contracts.py`, `tests/unit/test_sdk_capture.py` (mutants M6962–M6976, `scripts/mutants/SDK1b.py`).

### Fixed
- **The audit's compute check no longer reports a VM unreadable when its body leaves out `dataDisks`** (SDK1b, #1017). The SDK hands on `None`, never `[]`, and the check failed with « 'NoneType' object is not iterable ». It now reads such a VM as having no data disk.
