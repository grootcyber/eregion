### Fixed
- **The logs' freshness reads again: its column is no longer a word of KQL, and a failed read says Azure's inner error** (LOGF1c, #1212; `docs/glorfindel.md`, `docs/operations.md`, « La fraîcheur des journaux »). In 0.6.8 every freshness read failed, on every table, with « HTTP 400 — (BadArgumentError) The request had some invalid properties », and the tiles of Entra ID and of the control plane went red while the rules read the same tables without an error. The query named its column `last`, a word of KQL (`nulls last`): a syntax error that Log Analytics answers in a 400. Measured in the workspace's editor on 26/11: `AuditLogs | where TimeGenerated > ago(48h) | summarize last = max(ingestion_time())` fails, the same query with `LastIngest =` answers (G0 had measured the same on 19/10, `docs/azure.md`). The column is now `LastIngest`, read under that name. A guard on the text, `glorfindel/kql.py` (`reserved_names`), refuses a column named with a word of KQL, the name before a `=` after `summarize`, `extend`, `project`, `by` or a comma; it holds this module's query, which it would have refused in 0.6.8, the shipped rules, and every string of `glorfindel/` that holds a `|` (read by the AST). It does not see the rules the model writes (`detection_authoring`, `propose-rules`), the client's layer of rules, Gothmog's `verify` probes (they name `LastSeen` already), nor a name written `let last = …;`, `(a, last) = arg_max(…)` or `as last`. `short_error` now says first the deepest inner error of an Azure answer (`HttpResponseError.error.innererror`, nested, or the JSON after « Inner error: » in its text), its code and message masked of GUIDs and URLs and cut at 160 characters, then its first line as before: `HTTP 400 — SYN0002: Query could not be parsed at 'last' on line [3,13] — (BadArgumentError) The request had some invalid properties`. A failed read still opens no `logs_silent` card, as in 0.6.8.
