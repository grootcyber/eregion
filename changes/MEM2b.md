### Added
- **The precedent says its human verdict, behind the switch of the memory by keys** (MEM2b, #1161; `docs/design/memoire.md`, §9.5). On the harness's first passage of 24/11, the keys showed two former isolations on a modest disk write, and the model isolated wrongly, three times out of three: a precedent said the action, never how it was judged. With `GLORFINDEL_MEMORY=cles`, each precedent now ends with the verdict of the card its cycle opened (`right`, `wrong`, `unsure`, given in the console, the bot or `glorfindel verdict`), with its day: « décision jugée juste (vraie attaque) » when the decision responded, « (fausse alerte) » when it did nothing, « décision jugée fausse (…) », « incertain », or « non jugé ». Read when the precedents are chosen, never stored with the cycle; never the operator's note. Among the cycles of the same rule, VM and technique, a judged one comes before an unjudged one, never before one that shares more of the keys; `unsure` is said, never preferred. Off, nothing changes: the memory by distance gives no verdict, the message to the model is unchanged to the byte (the sha256 test). On, what the model sees changes: it waits for the end-to-end run of ENQ5b.
  - Tests: `tests/unit/test_memory_verdicts.py`, `tests/unit/test_memory_keys.py`; mutants M7433–M7438 (`scripts/mutants/MEM2b.py`).
- **The memory by keys that does not open falls back on the distance, said loud** (MEM2b, #1161; `docs/operations.md`, « La mémoire par clés »). A directory left to root by docker, a file that is no SQLite database, the ChromaDB folder given as its path: the watch (and `respond`, a restore) decides on the memory by distance, says it on stderr, in red on its banner and on a card of its own (`memory_fallback`, out of TO JUDGE), closed at the next start that opens the keys. An unknown value of the switch is said the same way. `glorfindel memory-stats` refuses instead (exit 2); a given mode (the harness) raises; the store guard's refusal in an agent session stays a refusal. `deploy.sh` says a `~/.eregion/watch-memory` that is not the operator's, without stopping the deploy, and `make fix-state-ownership` gives it back.
  - Tests: `tests/unit/test_memory_verdicts.py`; mutants M7439–M7440.
- **The harness's first passage replays with verdicts** (MEM2b, #1161; `docs/operations.md`, « Le harnais des précédents »). The history of each case is the one of 24/11, unchanged; its cycles now carry the verdict of their card (a containment judged right, a closed decision judged right, the oldest of one VM never judged), read by the memory by keys only. The keys choose the same cycles as on 24/11. `make llm-compare … PRECEDENTS=1`, about $1.2, the maintainer's.
  - Tests: `tests/unit/test_harness_precedents.py`; mutant M7442.
