### Added
- **Each reader of Log Analytics rows in Glorfindel is tested at least once on the pinned SDK's own objects, never only on lists a test made up** (SDK1a, #992; `docs/design/preuves.md`, « Les couches »). Most of these tests handed the readers the rows of `tests/unit/kql_subset.py`: a `dynamic` column as a Python list, a date as the test wrote it. The SDK hands a `dynamic` column on as its JSON text and a `datetime` column as a `datetime`; SLF1 passed its tests that way and did nothing in production (SLF1b). A shared test utility, `tests/unit/sdk_logs.py`, writes the body of a reply as the service sends it, its columns typed (`string`, `int`, `long`, `real`, `datetime`, `dynamic`, `bool`, `guid`, `timespan`), and has it read by the pinned `LogsQueryClient` itself, over azure-core's own transport: only the socket is replaced, and the query and the window the client sends are kept. The two files that already read the SDK's objects now use it. Read through it: the detector's `run_query` and `poll_alert` (every table, a partial reply raised, the SDK's `HttpResponseError` let through), the Activity Log's adapter (an NSG write named by its caller, Glorfindel's own write named by its `Claims_d`, the drain of an isolation by its `Started`), Entra ID's adapter (its thresholds on numbers, its marks, a boolean `AdminConsent`, the plan's hour), the rule poller and the correlation (a brute force and its login, a root shell from a declared origin), the discovery's last heartbeat, the audit's counts, `rules check` (its rows, and the kind and KQL code of the SDK's errors: a missing table, a syntax error, 403, 404, a partial reply), the schema read before authoring, the enquiry of `investigate` (its rows rendered for the model as before, a refused query a gap) and the campaign replay. No reader was found wrong on the shipped rules. One divergence is written as a known limit, not fixed here: an aggregated row (without `TimeGenerated`) that carries a `dynamic` column changes identity when that column's content changes; no shipped rule has one.
  - Tests: `tests/unit/test_sdk_contracts.py`, `tests/unit/test_own_channel_sdk.py`, `tests/unit/test_control_plane_unreadable.py`, `tests/unit/test_campaign_replay.py`, `tests/unit/test_entra_msi.py` (the rows of 20/11 set aside by MID1 through the SDK), `tests/unit/test_dependency_lock.py`. Mutants M6820–M6824 (`scripts/mutants/SDK1a.py`).

### Changed
- **Glorfindel's extra requires `azure-monitor-query>=2.0`, the version its readers are tested on** (SDK1a, #992). It admitted `>=1.3`, a release line no test reads. The lock does not move (it pins 2.0.0), and a test holds the floor to the major version the lock pins: a lock moved to another major fails until the floor follows it. The injectors' extra keeps its bound: its reader follows in a later lot (part of #992, by the other Orchestra).
