### Changed
- **The analysis index on a SQLite table of its own, without ChromaDB: the same rows in the same order, the old index imported once and offline, and said until it is** (MEM3, #1029; `docs/analysis.md`, « L'index sur une table, sans ChromaDB »; `docs/design/memoire.md`, §7, Q5). The index of the campaign report was a ChromaDB collection read by keys only, never by similarity. It is now one table, `campaign_runs`, in `~/.eregion/analysis/index.sqlite` (`EREGION_ANALYSIS_INDEX` names another file), in the standard library, with an index on each key the reads use (`analysis/run_index.py`). Its callers keep their interface, and it answers as the collection answered, measured against chromadb 1.5.9: the rows in the order they were first put in, an upsert that keeps a row's place and merges its keys. The reports of the example campaigns of D-2 are the same to the byte; an index of before, migrated, gives the same rows in the same order. `analysis/` no longer imports chromadb but to migrate; chromadb stays a dependency until MEM4. Glorfindel's model and what it reads do not change.
  - The import, once: `python -m analysis.index_import <old index> [--to <table>]` copies the old index into a temporary working folder, opens only that copy with ChromaDB (telemetry off, no model, no network), and puts each row not yet in the table at the end, in the old order. A row already in the table is kept and named; a row whose facts cannot be read is never written, and named. It refuses a table in the folder it reads, a folder that is not a ChromaDB index or holds a link, and anything in Glorfindel's state. Until the old index (`chroma/`, beside the table) is imported, each report says so in one line, and `campaign_index` refuses to put campaigns in, which would compute their runs again with an unknown decision.
  - The separation of IA1 under the new form: a file that holds Glorfindel's memory (its table `cycles`, the form MEM2 will give it) is refused at its opening as the index, wherever it lies, and nothing is written in it (but the rollback of a hot journal, MEM3b); a file of ChromaDB, its form of today, is refused too (MEM3b). A file in `~/.glorfindel` is refused before it is made.
  - A row that cannot be read is never an empty run: facts that are no object, without a run id, or another run's are left out (before, facts that were no object broke the report). A file that is no database raises; a folder at the index's path, the old index, is refused with the import's command.
  - In an agent session, the operator's `~/.eregion/analysis` is refused at the table's opening by the guard's audit hook (`sqlite3.connect`): the explicit check ChromaDB needed is gone (HY2c's M5240 now measures that event; M5241 is retired).
  - Kept as it was, said: `prior_runs` reads the first 50 rows of a technique in the order they came in, so past 50 runs of one technique the newest no longer come back, as under ChromaDB.
  - Tests: `tests/unit/test_analysis_index.py` (against the embedded chromadb client, its rows given an embedding of their own: no model fetched), and the analysis tests moved from chromadb to the table. Mutants M7035–M7039 (`scripts/mutants/MEM3.py`).
