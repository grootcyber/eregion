### Fixed
- **The weekly drill's service runs with the same options as the injector's runs on Orodruin, its executable run HOME included** (DRL1d, part of #613; `docs/design/drill-banc.md` §2.1, §15). The service's `ExecStart` (`infra/orodruin/drill_ops.py`) carried only the copy of `ORO_HARDEN`, not `ORO_EXEC_HOME` (`--tmpfs /stratus-home:exec`, R2BZ), the one executable tmpfs where the injector's control-plane adapter builds the run HOME and Terraform executes its providers: a control-plane technique played by the drill would have failed where the same run launched by hand passes. It now carries `ORO_HARDEN` then `ORO_EXEC_HOME`, no more, no less; `/tmp` stays `noexec`, no capability, no privilege gained, the root read-only. The drill plays only the injector's runs (a technique, never a fault in v1); its reads (`fingerprint`, `check`) play none and keep `ORO_HARDEN` alone, as the contract's and Gothmog's runs. A test reads `ORO_HARDEN`, `ORO_EXEC_HOME` and `ORO_RUN` in the `Makefile`, expands them, and requires the service's execution options to be exactly `ORO_RUN`'s, every injector run def to carry the same, the executable tmpfs to be the adapter's path and the only executable one, and no HOME set another way. The change reaches Orodruin at the next arming, which rewrites the unit.
