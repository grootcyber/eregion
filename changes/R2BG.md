### Added
- **The guardrails for Stratus's dedicated test subscription, in Terraform** (R2BG, #608; `docs/design/stratus-cible.md`, § 6). The infrastructure the operator applies by hand (plan shown first) so the dedicated subscription is bounded before any run; nothing here is applied by a session, and nothing runs by default.
  - `infra/orodruin/stratus_guardrails.tf` adds three guardrails, all off until `stratus_guardrails_enabled` (default `false`): an **Azure Policy** set (allowed regions, resource types and VM SKUs from the built-in policies — each only assigned once its list is non-empty, since an empty allow-list in deny mode would refuse every creation; the allowed resource types carry the Bastion and its public IP — plus a custom definition that **denies a public IP on a network interface whenever any of its ipConfigurations has one** (`not { … notLike "*" }`, not the naive `[*]…exists`, which a mixed NIC would slip past), which the Bastion's own public-IP resource escapes, keeping "Orodruin without Internet"); a **subscription diagnostic setting** routing only the `Administrative` category of the dedicated subscription to the bench's Log Analytics workspace (the one-way bridge the watch reads, with no right on the dedicated subscription); and a **subscription budget** whose action group lives **outside** the dedicated subscription, in Orodruin's own group, so emptying the subscription (kill, COLD) never removes it.
  - A dedicated provider alias targets the dedicated subscription from its id, and a **`precondition`** (`terraform_data.stratus_guard`, which the guardrails depend on — a `check` would only warn, the apply would continue) refuses to point at Orodruin's own subscription, so a plan aimed at the wrong subscription fails before posing anything — the first line against the v1 blocker (rights reaching the whole bench); the full refusal (bench, VM, Imladris) will come from the contract (`eregion_core/orodruin.py`) in R2c, and does not exist yet.
  - The closed Stratus role and Orodruin's read-only grant on the dedicated subscription (G3, G4) are **not** written here: they wait on the minimal per-technique actions measured at the bench (M1).
  - `infra/orodruin/variables.tf` (the new variables, all empty/off by default), `infra/orodruin/outputs.tf` (the posed ids, null when off — never copied into the repo).
  - Tests: `tests/unit/test_stratus_guardrails.py` (off by default, the alias targets the dedicated subscription, every dedicated-subscription resource declares the `azurerm.stratus` provider, the diagnostic category, the action group outside the dedicated subscription, the any-ipConfig public-IP denial, no closed role yet), listed in `scripts/component_check.py`; `infra/orodruin/tests/stratus_guardrails.tftest.hcl` (a real plan proving the module is inert by default — zero guardrail resources, null outputs — and that the `precondition` refuses Orodruin's own subscription), with the `azurerm.stratus` alias mocked in the existing Orodruin tftests; mutants M5650–M5659 (`scripts/mutants/R2BG.py`).
