Autonomy is earned, VM by VM

Before Glorfindel acts alone outside the bench

Each one observed on real systems, none assumed.

  • Two writers on the same VM, caught and handled
  • A disruptive action taken alone only when several draws of the model agree
  • No high finding open on the isolation path
  • Reliable detection on the VMs it will defend
  • The ransomware threshold tuned on real benign traffic, across disk types
  • A real exercise on dedicated test VMs close to production: isolate, block, lift, back to the original state, verified
  • The suite measured: the harness above its threshold, the control set caught by half on every push and by three quarters at night
  • The subscription guard measured on a second real subscription
  • Four weeks in human_only on a real fleet, wrong disruptive recommendations measured and judged acceptable

Then activation VM by VM, starting with non-critical ones. Delete and wipe never act alone; a restore without a human is not decided: it would be a separate setting, empty by default and not read by the decision today; no fault or destructive test ever runs on a real workload.

On the road

  1. 0.6The identity defended. Azure activity and Entra ID logs flowing and measured; a Stratus Red Team technique against a test identity, seen by Glorfindel; the plan for a stolen identity on the card, with a Verify button.
  2. 1.0Autonomy in production. Allowed VM by VM once every criterion holds. A signed action queue, where only the watch writes. Public contracts frozen: signals, experiments, catalog, provider interface. Every profile proven in CI.
  3. 1.xMore clouds, more engines. AWS, then GCP, through the provider interface; Kubernetes faults; an attack during a fault, detected or escalated, never blind. Later, a hosted service.
